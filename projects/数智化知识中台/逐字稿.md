## 完整版（2-3分钟）

> 适用场景：「讲讲你最有成就感/印象最深的项目」

这个项目是我们部门的知识库系统，我是前端负责人。它是部门内第一个 Vue 3 项目，所以除了业务本身，我还做了很多基础建设的事情。

先说组件库。当时部门没有 Vue 3 的组件库，这个项目正好是第一个，时机合适，我就顺手把组件库一起建了。我们没有从零造轮子，而是基于 Element Plus 封装了一层。这样做有两个考虑：一是成本低，直接复用成熟库；二是解耦，业务代码只依赖我们自己的组件库，底层换 Element Plus 还是别的库，业务代码不用动。这套组件库后来被部门 5 个以上的 Vue 3 项目接入了。

同时我也输出了部门级的 Vue 3 + TypeScript 开发规范，统一了技术栈标准，后续新项目直接按规范来，不用每次重新讨论选型。

编辑器这块是这个项目里比较复杂的部分。我们选了 CKEditor，定制了 5 个以上的插件。其中让我印象最深的是一个"关联知识插入"插件。

背景是这样的：我们是知识库系统，编辑文章时经常需要引用其他知识点的内容。如果直接复制粘贴，原知识点更新了，这里的内容就过期了。所以我设计了一个插件，在编辑时插入的是一个占位符，预览时系统根据占位符动态拉取最新内容。你可以理解为一个"变量"，知识点内容变了，引用它的地方自动同步。

技术实现上有个关键点：插件只负责"插入"这个动作，数据从哪来、插什么内容，是业务层的事。所以我设计了一套事件机制，插件触发事件，业务层响应并把数据传回来，职责分离得比较清楚。

还有一块是知识锚点 SDK，支持催收、客服、电销等业务条线接入，让他们在自己的系统里能快速查询和展示知识库内容。SDK 对外提供统一接口，内部通过条线编码走不同的业务分支，适配各条线的差异化需求。同时我也输出了部门级的 SDK 开发规范，后续其他同学开发 SDK 有了参考。

这个项目做完之后，组件库、规范、SDK 后来被部门其他项目陆续用起来了，不只是这一个项目在用。

## 简短版（30秒）

> 适用场景：面试官扫简历时快速介绍

我在马上消费金融主导建设了部门知识中台，这是部门第一个 Vue 3 项目。除了业务交付，我还搭建了部门级 Vue 3 组件库和开发规范，组件库被 5 个以上项目接入。编辑器基于 CKEditor 定制了多个插件，其中关联知识插入插件通过占位符动态拉取内容，解决了知识引用过期的问题。同时主导了知识锚点 SDK 的设计，支持多业务条线接入。
