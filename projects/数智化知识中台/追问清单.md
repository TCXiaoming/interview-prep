## Q1：CKEditor 5 的插件机制是怎样的？怎么注册一个插件？

CKEditor 5 的插件是一个继承 `Plugin` 类的 class，通过 `editor.builtinPlugins` 数组注册，或通过 `config.extraPlugins` 追加。

插件生命周期方法：
- `init()` — 编辑器初始化时调用，常用于注册命令、绑定事件、注册 schema
- `afterInit()` — 初始化完成后调用
- `destroy()` — 编辑器销毁时调用，做清理工作

```js
import Plugin from '@ckeditor/ckeditor5-core/src/plugin';

class MyPlugin extends Plugin {
  init() {
    const editor = this.editor;
    // 注册命令、事件、schema 等
  }
  afterInit() {
    // 初始化后逻辑
  }
  destroy() {
    // 清理
  }
}
```

## Q2：关联知识插入插件的完整流程是什么？

三层架构：插件负责 UI 动作和编辑器内渲染，业务层负责数据获取，通过事件解耦。

1. **用户触发**：点击编辑器工具栏的"插入关联知识"图标（插件注册的 UI 按钮）
2. **事件触发**：插件触发自定义事件，业务层监听该事件
3. **业务层处理**：弹出知识选择弹窗，用户选择知识后，业务层调用插件暴露的方法，传入选中的知识数据
4. **插件渲染**：插件将数据插入到编辑器 model 中，以 inline widget 形式展示为占位符（显示知识标题，样式像一个小卡片）
5. **预览时**：占位符转为链接/下载入口，不是内嵌内容

设计要点：插件不关心数据从哪来、插什么内容，只负责"插入"这个动作和编辑器内渲染。职责通过事件机制分离。

## Q3：占位符在 CKEditor 5 数据模型里是什么？怎么做成卡片样式的？

用 **Inline Widget** 实现，分三层：

1. **Schema 层**：注册自定义 element（如 `knowledgeRef`），设置 `isInline: true`，让它像图片一样是行内的、不可分割的单元
2. **转换层**：
   - Downcast（model → view）：将 `knowledgeRef` 转换为带样式的 `<span>`，显示知识标题，看起来像小卡片
   - Upcast（view → model）：将 HTML 中的占位符转回 model element，保证数据不丢失
3. **Widget 行为**：用 `toWidget()` 让它有选中态、不可编辑内部内容，但可以整体删除或移动

## Q4：预览时关联知识怎么渲染？性能怎么保证？

预览时不内嵌知识内容，而是：
- 原始知识、服务知识 → 转为跳转链接
- 文档知识 → 提供跳转和下载两种方式

不存在"拉取所有关联知识内容渲染"的性能问题。性能瓶颈集中在文档知识详情页，通过前后端分批拉取（分片加载）解决。

## Q5：文档知识详情页的分片加载怎么实现的？

后端按标题（H 标签）将文档切分为单元（约 500 字符一个），前端以分页方式逐批拉取。

当前方案：滚动到底部时自动加载下一批，类似上拉加载更多。

可优化方向（虚拟滚动 + 按需加载）：
1. 后端切分段落单元，返回时带分页信息
2. 前端用 `IntersectionObserver` 监听每个段落占位元素，滚入视口时触发加载
3. 已加载的内容保留，未加载的只渲染骨架屏
4. 用户可跳着滚到中间某个标题，不用等前面全部加载完

## Q6：改 CKEditor 源码过程中遇到什么问题？

核心问题是事件冲突，有两个典型场景：

### 场景一：右键菜单与表格插件冲突

**现象**：右键单个单元格时，表格插件的事件处理先跑，把选中状态改成了选中整个表格，自定义菜单拿到的选中信息就错了。而且表格插件内部调用了 `stopPropagation`，导致自定义菜单事件有时候收不到，表现不稳定。

**排查过程**：一开始以为是插件注册顺序问题，调整后没用。后来用 DevTools 事件监听器断点，发现同一个 `contextmenu` 事件上挂了多个处理函数，执行顺序不确定。

**解决方案**：把右键菜单逻辑从具体元素上移开，挂到更上层的 `view.Document` 上，用事件代理统一拦截。在回调里自己判断当前选中 element 类型（`<tableCell>` 还是 `<table>`），再决定弹出哪个菜单。绕开表格插件内部的事件控制权，自己在最外层做分发。

### 场景二：图片拖拽与表格选中冲突

**现象**：在表格里拖拽图片想调整大小，表格插件以为用户在选中多个单元格，把图片的拖拽事件抢走了。

**解决方案**：判断事件源 element 类型，如果拖拽目标是图片 element，就阻止表格插件的选中行为，走图片自己的拖拽逻辑。
