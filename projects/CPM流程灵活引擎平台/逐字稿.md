## 完整版（2-3分钟）

> 适用场景：「讲讲你最有成就感/印象最深的项目」

这个项目是我们部门自建的流程编排与审批平台，我是前端负责人。

说说为什么要做这个。当时我们用的审批系统是从公司其他部门借来的，不是我们自己的。上层评估之后发现，这套系统我们没有自主权，想改什么、想加什么功能，都要去协调别的团队，周期很长。而且那套系统本身体验也不太好，定制化程度不够，很多业务诉求满足不了。所以决定自己建一套。

技术上最费时间的是流程编排这块。我们用了 bpmn-js 这个库，它是一个标准的 BPMN 流程图编辑器，开箱即用的样式和交互跟我们的产品风格差很多。我们需要深度定制，包括自定义节点的渲染（Renderer）、左侧工具栏（Palette），还有右侧的属性面板（Property Panel）。

属性面板这块花的时间最多。bpmn-js 的属性面板扩展文档比较少，很多东西要去翻源码才能搞清楚数据怎么流转、怎么跟节点绑定。我们当时花了不少时间研究它的数据层，才把业务需要的审批人配置、表单绑定这些属性做进去。

另一件我比较在意的事是 Code Review 机制。之前团队的 CR 做得很随意，代码风格五花八门，而且出过几次生产问题，直接影响了绩效。所以我推动建立了一套 CR 流程：提测前必须过 CR，重点模块深度 Review，其他模块轻度过，同时制定了 Checklist，对照需求逐条核查代码是否覆盖。

这套机制推下来，CR 率稳定在 90% 以上，线上问题逃逸率降到了 1% 以下。

最终这个平台替换了原来的旧系统，接入了 5 个以上的新业务审批场景，新业务上线周期比之前快了很多，不用再等其他团队排期了。

## 简短版（30秒）

> 适用场景：面试官扫简历时快速介绍

我在马上消费金融主导建设了一个流程编排与审批平台，替换了原来没有自主权的借用系统。基于 bpmn-js 做了很多定制，改了节点渲染、工具栏，属性面板这块翻了不少源码才搞清楚。同时推动建立了 Code Review 机制，CR 率 90% 以上，线上问题逃逸率控制在 1% 以下，平台最终接入了 5 个以上新业务审批场景。
