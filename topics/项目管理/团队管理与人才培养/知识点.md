# 团队管理与人才培养

## 核心概念

### 前端团队管理的关键维度

1. **技术方向** — 技术选型、架构演进、规范建设
2. **项目交付** — 排期管理、风险控制、质量保障
3. **人才培养** — 招聘、培训、晋升辅导
4. **文化建设** — 技术氛围、Code Review 文化、分享机制

### 管理幅度与角色定位

| 角色 | 关注点 | 核心动作 |
|---|---|---|
| 一线开发 | 写好自己的代码 | 编码、自测、提 PR |
| Tech Lead | 带好一个小组 | 方案设计、Code Review、任务分配 |
| 前端负责人 | 管好一条线 | 技术规划、跨团队协调、人才培养 |
| 架构师 | 定好技术方向 | 架构设计、技术决策、技术影响力 |

### 人才梯队建设

```
初级 → 中级 → 高级 → 专家
  ↓       ↓       ↓      ↓
能完成   能做好   能带人   能定方向
明确任务 独立负责 培养他人 技术决策
```

培养手段：
- **导师制** — 新人配一个 mentor，负责日常指导
- **Code Review** — 最直接的代码能力提升手段
- **技术分享** — 团队内部轮流分享，锻炼表达能力和深度思考
- **挑战性任务** — 给有潜力的人超出当前能力的任务，拉伸成长
- **复盘文化** — 每个项目结束做复盘，沉淀经验教训

## 常见追问

### Q: 你的团队有多少人？你是怎么分工的？

**回答要点：**
- 说清楚团队规模、人员构成（初级/中级/高级各多少人）
- 分工逻辑：按业务线分、按技术模块分、还是混合模式
- 举例说明你怎么给不同能力的人分配不同难度的任务

### Q: 怎么推动技术规范在团队中落地？

**回答要点：**
1. **工具先行** — 用 ESLint/Prettier/Husky 强制执行，减少人为依赖
2. **以身作则** — 自己先严格遵守，Review 时严格要求
3. **渐进式推行** — 不要一次性出太多规范，从影响最大的几条开始
4. **文档化** — 写清楚规范是什么、为什么这样定、怎么执行
5. **定期 Review** — 规范不是定了就完事，要定期检查执行情况

### Q: 团队成员能力差距大，你怎么处理？

**回答要点：**
- **分层任务** — 复杂任务给能力强的人，简单任务给新人，但要给新人成长空间
- **结对编程** — 让新人和老人一起做一个任务，边做边学
- **知识文档化** — 把常见问题和解决方案写成文档，降低新人学习成本
- **定期 1on1** — 了解每个人的成长诉求和困惑，针对性指导

### Q: 招人的时候你看重什么？

**回答要点：**
1. **基础扎实** — JS/CSS 基本功，不是背八股文，是真正理解
2. **解决问题的能力** — 给一个实际问题，看他怎么拆解、怎么思考
3. **学习能力** — 技术栈会变，学习能力不会
4. **沟通表达** — 前端需要和产品、设计、后端协作，沟通能力很重要
5. **技术热情** — 有没有自己的技术追求，而不是纯完成任务

## 回答要点总结

1. 用自己实际的管理经验来回答，不要背管理学理论
2. 有具体数据支撑 — 团队多少人、培养了几个人晋升、规范落地后效果如何
3. 体现你的管理风格 — 是偏向技术驱动还是流程驱动
4. 能说出踩过的坑 — 比如推行规范时遇到的阻力、招人看走眼的经历
