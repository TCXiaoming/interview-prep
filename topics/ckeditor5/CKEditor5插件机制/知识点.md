# CKEditor 5 插件机制

## 核心概念

CKEditor 5 的插件系统是其核心架构，编辑器本身也是由一组内置插件组合而成。每个插件是一个继承 `Plugin` 类的 class，通过编辑器的 `builtinPlugins` 或 `config.extraPlugins` 注册。

### Plugin 基础结构

```js
import Plugin from '@ckeditor/ckeditor5-core/src/plugin';

class MyPlugin extends Plugin {
  static get requires() {
    // 声明依赖的其他插件
    return [ OtherPlugin ];
  }

  static get pluginName() {
    return 'MyPlugin';
  }

  init() {
    // 编辑器初始化时调用
    // 注册命令、schema、绑定事件、注册 UI 组件
    const editor = this.editor;
  }

  afterInit() {
    // 初始化完成后调用
    // 适合做依赖其他插件的初始化逻辑
  }

  destroy() {
    // 编辑器销毁时调用，做清理
  }
}
```

### 插件注册方式

```js
// 方式一：在编辑器类的 builtinPlugins 中注册（最常用）
class MyEditor extends ClassicEditor {}
MyEditor.builtinPlugins = [ MyPlugin ];

// 方式二：通过 extraPlugins 配置追加
ClassicEditor.create(element, {
  extraPlugins: [ MyPlugin ]
});
```

### 插件分类

- **功能插件**：提供编辑能力（如 Bold、Link、Image）
- **UI 插件**：提供工具栏按钮、下拉菜单等界面
- **转换插件**：负责 model ↔ view 的数据转换
- **业务插件**：自定义的业务逻辑插件（如关联知识插入）

## 架构三层模型

CKEditor 5 的核心架构分三层：

### 1. Model（数据模型）

编辑器内部的数据表示，是树形结构，与 HTML 不同。

```js
// Schema 定义：声明自定义 element 的规则
editor.model.schema.register('knowledgeRef', {
  isInline: true,       // 行内元素（类似 <span>）
  isObject: true,       // 不可分割的整体（类似图片）
  allowWhere: '$text',  // 允许出现在文本位置
  allowAttributes: [ 'knowledgeId', 'knowledgeTitle' ]
});
```

### 2. View（视图层）

CKEditor 5 自己的视图抽象层，**不是浏览器 DOM**，也不是 Vue/React 的虚拟 DOM。它是 CKEditor 独立维护的一棵 View 树，有自己的 `ViewDocument`、`ViewElement`、`ViewText` 等节点类型。

关键理解：
- View 层是 CKEditor 与浏览器 DOM 之间的中间层
- CKEditor 通过自身的 rendering pipeline 将 View 树同步到真实 DOM
- 插件操作的是 View 树，不直接操作 DOM（这就是为什么改源码时要在 View 层操作）
- `view.Document` 是 View 层的根，所有 View 元素都挂在其下

```js
// View 层常见操作
const viewDocument = editor.editing.view.document;
const viewRoot = viewDocument.getRoot();          // 获取根 ViewElement
const viewSelection = viewDocument.selection;      // 获取 View 选区

// 创建 View 元素
const viewWriter = editor.editing.view.change(writer => {
  const element = writer.createContainerElement('div', { class: 'my-widget' });
  const text = writer.createText('Hello');
  writer.insert(writer.createPositionAt(element, 0), text);
  return element;
});
```

### 3. Conversion（转换层）

Model 和 View 之间的双向转换，是插件开发的核心。CKEditor 内部维护 Model 树和 View 树两套数据结构，Conversion 负责它们之间的同步。

```
用户输入 / paste / setData()
        ↓ (Upcast)
    Model 树
        ↓ (Downcast → 碰撞检测 → Rendering)
    View 树
        ↓ (Rendering)
    真实 DOM
```

- **Upcast**：View → Model，发生在加载内容、粘贴时
- **Downcast**：Model → View，发生在 model 数据变化时
- Downcast 又分为 **editing downcast**（编辑态，每次变化都重跑）和 **data downcast**（数据导出时）

**Downcast（model → view）**：数据模型转成用户看到的内容

```js
editor.conversion.for('downcast').add(dispatcher => {
  dispatcher.on('insert:knowledgeRef', (evt, data, api) => {
    const viewWriter = api.writer;
    const widgetElement = viewWriter.createContainerElement('span', {
      class: 'knowledge-ref-widget',
      'data-knowledge-id': data.item.getAttribute('knowledgeId')
    });
    const innerText = viewWriter.createText(data.item.getAttribute('knowledgeTitle'));
    viewWriter.insert(viewWriter.createPositionAt(widgetElement, 0), innerText);
    api.mapper.bindElements(data.item, widgetElement);
  });
});
```

**Upcast（view → model）**：HTML 转回数据模型

```js
editor.conversion.for('upcast').add(dispatcher => {
  dispatcher.on('element:span', (evt, data, api) => {
    if (!data.viewItem.hasClass('knowledge-ref-widget')) return;
    const knowledgeId = data.viewItem.getAttribute('data-knowledge-id');
    const knowledgeTitle = data.viewItem.getChild(0).data;
    const modelElement = api.writer.createElement('knowledgeRef', {
      knowledgeId,
      knowledgeTitle
    });
    api.writer.insert(modelElement, data.modelCursor);
    api.consume(data.viewItem);
  });
});
```

## Widget（小部件）

Widget 让自定义元素有交互行为：选中态、不可编辑内部、可整体操作。

```js
import { toWidget } from '@ckeditor/ckeditor5-widget/src/utils';

// 在 downcast 中将 view 元素包装为 widget
const widgetElement = viewWriter.createContainerElement('span', {
  class: 'knowledge-ref-widget'
});
toWidget(widgetElement, viewWriter);
```

Widget 特性：
- 点击选中整个元素，不能编辑内部文本
- 可以整体删除、移动
- 有选中态高亮
- 按方向键时跳过整个 widget，不会停在中间

## 使用 Vue/React 作为 UI 层

CKEditor 5 自带的 UI 系统（View 层 + Balloon、Dropdown 等组件）功能完整，但样式和交互受限于 CKEditor 内部实现。实际项目中，复杂 UI（弹窗、选择器、富交互面板）更常见的做法是：**CKEditor 只管编辑核心，UI 交给 Vue/React 渲染**。

核心思路：在 CKEditor 插件中创建一个 DOM 容器，将 Vue/React 组件挂载上去，插件销毁时清理。

### 通用模式

```
CKEditor Plugin (编辑核心)
    ↓ 通过事件通信
Vue/React 组件 (UI 层)
    ↓ 渲染到
CKEditor View 中的 DOM 容器
```

### Vue 作为 UI 层

```js
// CKEditor 插件中
import Plugin from '@ckeditor/ckeditor5-core/src/plugin';
import { createApp } from 'vue';
import KnowledgePicker from './KnowledgePicker.vue';

class KnowledgeInsertPlugin extends Plugin {
  init() {
    const editor = this.editor;

    // 1. 注册工具栏按钮
    editor.ui.componentFactory.add('knowledgeInsert', locale => {
      const button = new ButtonView(locale);
      button.set({ label: '插入知识', withText: true });

      button.on('execute', () => {
        // 2. 创建 DOM 容器，挂载 Vue 组件
        const container = document.createElement('div');
        document.body.appendChild(container);

        const app = createApp(KnowledgePicker, {
          // 3. Vue 组件选中知识后，通过回调传回 CKEditor 插件
          onSelect: (knowledge) => {
            editor.model.change(writer => {
              const ref = writer.createElement('knowledgeRef', {
                knowledgeId: knowledge.id,
                knowledgeTitle: knowledge.title
              });
              editor.model.insertContent(ref);
            });
            app.unmount();
            container.remove();
          },
          onCancel: () => {
            app.unmount();
            container.remove();
          }
        });

        app.mount(container);
      });

      return button;
    });
  }
}
```

### React 作为 UI 层

```js
// CKEditor 插件中
import Plugin from '@ckeditor/ckeditor5-core/src/plugin';
import { createRoot } from 'react-dom/client';
import KnowledgePicker from './KnowledgePicker';

class KnowledgeInsertPlugin extends Plugin {
  init() {
    const editor = this.editor;

    editor.ui.componentFactory.add('knowledgeInsert', locale => {
      const button = new ButtonView(locale);
      button.set({ label: '插入知识', withText: true });

      button.on('execute', () => {
        // 创建容器
        const container = document.createElement('div');
        document.body.appendChild(container);
        const root = createRoot(container);

        const handleSelect = (knowledge) => {
          editor.model.change(writer => {
            const ref = writer.createElement('knowledgeRef', {
              knowledgeId: knowledge.id,
              knowledgeTitle: knowledge.title
            });
            editor.model.insertContent(ref);
          });
          root.unmount();
          container.remove();
        };

        root.render(
          <KnowledgePicker onSelect={handleSelect} onCancel={() => {
            root.unmount();
            container.remove();
          }} />
        );
      });

      return button;
    });
  }
}
```

### 在编辑器内部嵌入框架组件

如果需要在编辑器内容区域里渲染 Vue/React 组件（比如 widget 内嵌复杂 UI），做法是：

1. Downcast 时创建一个空的 DOM 容器
2. 将框架组件挂载到这个容器上
3. 通过 CKEditor 的 `DomConverter` 将容器插入 View 树

```js
// Downcast 中嵌入 React 组件
editor.conversion.for('downcast').add(dispatcher => {
  dispatcher.on('insert:myWidget', (evt, data, api) => {
    const domRoot = api.mapper.toViewElement(data.item);

    // 创建一个 DOM 容器
    const reactContainer = document.createElement('div');
    reactContainer.setAttribute('data-react-widget', 'true');

    // 挂载 React 组件
    const root = createRoot(reactContainer);
    root.render(<MyWidget data={data.item.getAttribute('widgetData')} />);

    // 插入到 View 中
    const viewElement = api.writer.createUIElement('div', {
      class: 'widget-container'
    });
    viewElement.render = function(domDocument) {
      const domElement = this.toDomElement(domDocument);
      domElement.appendChild(reactContainer);
      return domElement;
    };
    api.writer.insert(api.writer.createPositionAt(domRoot, 0), viewElement);
  });
});
```

### 关键注意事项

1. **生命周期管理**：插件 `destroy()` 时必须清理挂载的 Vue/React 实例，否则内存泄漏
2. **事件通信**：CKEditor 插件与框架组件之间通过回调函数或事件总线通信，不要让组件直接引用 editor 实例
3. **编辑器选区**：框架组件获得焦点时，CKEditor 的选区可能会丢失。如果需要保持编辑器选区，要在组件聚焦前保存选区，失焦后恢复
4. **弹窗/浮层定位**：以编辑器的选区位置（`editor.model.document.selection`）或光标 DOM 位置为锚点定位，而不是以视口

4. 如何给插件注册工具栏按钮？
5. 插件之间的依赖关系怎么管理？（`static get requires()`）

7. 事件系统中 `stopPropagation` 和 `evt.stop()` 的区别？

## 回答要点

### CKEditor 4 vs CKEditor 5

| 对比 | CKEditor 4 | CKEditor 5 |
|------|-----------|-----------|
| 数据模型 | 直接操作 DOM | 自定义 Model → View → DOM |
| 插件注册 | `CKEDITOR.plugins.add()` + `extraPlugins` | `Plugin` 类 + `builtinPlugins` |
| 架构 | 事件驱动，耦合 DOM | MVC 分层，数据与视图分离 |
| 可定制性 | 修改 DOM 输出 | 通过 schema + conversion 控制数据结构 |

### 插件间依赖管理

通过 `static get requires()` 声明依赖，编辑器初始化时按依赖顺序加载插件。依赖的插件不存在时编辑器会报错。

### 插件注册工具栏按钮

```js
// UI 插件通常拆成两部分：
// 1. 插件逻辑（Plugin）
// 2. 按钮 UI（ButtonView）

import ButtonView from '@ckeditor/ckeditor5-ui/src/button/buttonview';

class MyUI extends Plugin {
  init() {
    const editor = this.editor;
    editor.ui.componentFactory.add('myButton', locale => {
      const button = new ButtonView(locale);
      button.set({ label: 'My Button', withText: true });
      button.on('execute', () => {
        // 点击后执行逻辑
        editor.execute('myCommand');
      });
      return button;
    });
  }
}

// 工具栏配置
ClassicEditor.create(element, {
  toolbar: [ 'myButton', '|', 'bold', 'italic' ]
});
```

## 项目实战要点

### 插件与业务层解耦

插件不关心数据来源，通过事件机制与业务层通信：

1. 插件触发事件（如 `knowledgeInsert`）
2. 业务层监听事件，获取数据（如弹窗选择知识）
3. 业务层调用插件暴露的方法，传入数据
4. 插件将数据插入 model，完成渲染

### 源码改造常见坑

1. **事件冒泡冲突**：多个插件监听同一事件（如 `contextmenu`），执行顺序不确定。解决方案：挂到更上层的 `view.Document` 做事件代理，自己判断 element 类型分发
2. **Selection 冲突**：CKEditor 5 的选区是自定义的 `model.DocumentSelection`，不是浏览器原生 Selection。自定义拖拽等交互需要处理好与 CKEditor 选区机制的关系
3. **Command 注册冲突**：不同插件注册的 Command 如果操作同一个 model 结构，需要确保操作不互相覆盖
