# 富文本编辑器通用知识 - 常见问题

## Q1：contentEditable 有什么问题？为什么现代编辑器不用它做编辑逻辑？

contentEditable 是浏览器原生的富文本编辑能力，但存在以下问题：

1. **浏览器差异**：相同操作（如加粗、回车），不同浏览器产生的 HTML 不同
2. **光标不可控**：嵌套结构下光标行为不可预测，容易丢失
3. **粘贴不可控**：无法精细控制粘贴内容的格式清洗
4. **撤销/重做不可控**：`document.execCommand` 已废弃，浏览器自带的撤销栈无法自定义
5. **协同编辑不可行**：直接操作 DOM 没有可描述的操作序列，无法做 OT/CRDT

现代编辑器的做法：contentEditable 只是"壳"，内部用独立的 Model 管理数据，DOM 只是渲染结果。

## Q2：为什么要做独立的 Model 层？直接操作 DOM 不行吗？

直接操作 DOM 的问题：
1. DOM 不是数据模型，是渲染结果。DOM 结构变化时无法精确描述"改了什么"
2. 不同浏览器 DOM 行为不同，难以保证输出一致
3. 无法做协同编辑——协同需要描述"操作"，而不是"DOM 变化"
4. 撤销/重做需要记录操作序列，DOM 没有这个概念

Model 层的好处：
- 数据与渲染分离，输出格式完全可控
- 每次修改都是可描述的 Operation（insert、delete、setAttribute）
- Operation 可以用于 OT/CRDT 协同
- Operation 可以做撤销栈

## Q3：协同编辑怎么实现的？OT 和 CRDT 有什么区别？

**OT（Operational Transformation）**：
- 将编辑操作转换为 Operation 序列
- 服务端对并发操作做 transform，保证最终一致
- 需要中心服务器
- 代表：Google Docs、CKEditor 5

**CRDT（Conflict-free Replicated Data Type）**：
- 数据结构本身保证合并无冲突
- 不需要中心服务器，可去中心化
- 网络开销较大（需要维护元数据）
- 代表：Yjs、Automerge

简单说：OT 依赖服务器做转换，CRDT 数据结构本身保证无冲突。OT 实现复杂但轻量，CRDT 实现简单但开销大。

## Q4：粘贴 Word 内容怎么处理？

1. 监听 `clipboardInput` 事件，获取 `text/html` 格式的剪贴板数据
2. 用 DOMParser 解析 HTML
3. 清洗：移除垃圾标签（如 `<o:p>`、`<w:*>`）、清除内联样式、保留白名单标签（`<b>`、`<i>`、`<a>` 等）
4. 将清洗后的 HTML 转换为 editor 的 model 数据插入

为什么要清洗：Word 产生的 HTML 有大量 Office 专有标签和内联样式，直接插入会破坏编辑器格式，还可能有 XSS 风险。

## Q5：输入法（IME）在编辑器里有什么坑？

输入法在 Composition 事件期间会临时修改 DOM，如果编辑器在这时同步 model，会导致输入法候选框消失或输入中断。

解决：在 `compositionstart` 和 `compositionend` 之间暂停 model 同步，等输入法确认后统一处理。

```js
let isComposing = false;

element.addEventListener('compositionstart', () => {
  isComposing = true;
});

element.addEventListener('compositionend', () => {
  isComposing = false;
  // 此时同步 DOM 变化到 model
  syncToModel();
});

element.addEventListener('input', () => {
  if (!isComposing) {
    syncToModel();
  }
});
```

## Q6：大文档场景下性能怎么优化？

1. **虚拟渲染**：只渲染可视区域的节点，类似虚拟列表
2. **增量更新**：只更新变化的部分，不重新渲染整个文档
3. **操作批处理**：多次操作合并为一次渲染（CKEditor 5 的 `model.change()`）
4. **防抖/节流**：对高频事件（input、selectionchange）做节流
5. **图片懒加载**：不在可视区域的图片不加载
6. **分片加载**：大文档按段落分片，滚动时按需加载

## Q7：撤销/重做怎么实现的？

两种方案：

**操作栈（主流）**：记录每次操作的正向和反向操作
- 撤销：执行反向操作
- 重做：执行正向操作
- 内存开销小，适合大文档
- 代表：CKEditor 5（Operation 有 `undo()` 方法）、Quill（Delta 可逆）

**快照**：每次操作保存完整文档快照
- 撤销：回退到上一个快照
- 实现简单，但内存开销大
- 适合小文档或简单场景

## Q8：如何保证编辑器输出的 HTML 安全？

1. **白名单过滤**：只允许特定标签和属性，其他全部移除
2. **协议过滤**：移除 `javascript:`、`data:` 等危险协议
3. **事件属性过滤**：移除 `onclick`、`onerror` 等事件属性
4. **用户输入转义**：对特殊字符做 HTML 实体转义
5. **后端二次校验**：不信任前端传入的 HTML，在后端重新过滤
