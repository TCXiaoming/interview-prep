# 事件循环 - 常见问题

## Q1：Promise.then 和 setTimeout(fn, 0) 谁先执行？为什么？

Promise.then 先执行。因为 Promise.then 的回调是微任务，setTimeout 的回调是宏任务。事件循环每一轮是：执行一个宏任务 → 清空微任务队列。脚本整体代码（第一个宏任务）执行完后，会先清空微任务队列，再执行下一个宏任务（setTimeout）。

```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);
// 输出：1, 4, 3, 2
```

## Q2：事件循环的每一轮具体是怎么执行的？

口诀："一个宏任务，清一次微任务"

1. 执行同步代码（本身就是一个宏任务）
2. 同步代码执行完 → 清空微任务队列（微任务中产生的新微任务也会被立即执行）
3. 浏览器渲染（如果需要）
4. 取下一个宏任务执行 → 回到步骤 2

**注意**：不是"先微后宏"，而是"每执行完一个宏任务就清一次微任务"。

## Q3：async/await 在事件循环中怎么执行？

`await` 后面的表达式立即执行，`await` 之后的代码相当于放在 `.then()` 回调中，是微任务。

```js
async function foo() {
  console.log(1);        // 同步
  await Promise.resolve();
  console.log(2);        // 微任务
}
foo();
console.log(3);
// 输出：1, 3, 2
```

## Q4：微任务中不断产生微任务会怎样？

会阻塞宏任务执行。如果微任务队列不断产生新的微任务，宏任务（包括 setTimeout、UI 渲染）永远轮不到，页面会卡死。

```js
// 危险示例：阻塞页面
function loop() {
  Promise.resolve().then(loop);
}
loop(); // setTimeout 永远不会执行
```

## Q5：requestAnimationFrame 在事件循环中的位置？

rAF 不属于宏任务也不属于微任务，它是浏览器渲染流程的一部分。执行时机：微任务清空之后、浏览器渲染之前。

执行顺序：宏任务 → 微任务 → rAF → 渲染 → 下一个宏任务
