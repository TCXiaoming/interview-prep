# 前端并发控制 - 常见问题

## Q1：Promise.all 和 Promise.allSettled 什么时候用哪个？

- `Promise.all`：需要所有请求都成功，一个失败就整体失败。适用于多个请求互相依赖的场景（如先拿用户信息再拿订单列表）
- `Promise.allSettled`：需要所有请求都执行完，逐个判断成功或失败。适用于批量操作场景（如批量删除，部分失败不影响其他）

```js
// 全部成功才更新 UI
const [user, orders] = await Promise.all([getUser(), getOrders()])
render(user, orders)

// 批量删除，记录哪些成功哪些失败
const results = await Promise.allSettled(ids.map(id => deleteItem(id)))
const failed = results.filter(r => r.status === 'rejected')
```

## Q2：如何控制并发请求数量？

用"池化调度"：维护一个执行中的任务集合，达到上限时用 `Promise.race` 等任意一个完成再继续。

核心逻辑：
1. 遍历任务列表，每个任务包装成 Promise
2. 加入 `executing` 集合
3. 如果 `executing.size >= limit`，`await Promise.race(executing)` 等一个完成
4. 完成后从集合中移除，继续下一个任务
5. 最后 `Promise.all(results)` 返回所有结果

## Q3：用户快速搜索时怎么处理竞态条件？

三种方案：

**方案一（推荐）：AbortController 取消旧请求**
```js
let controller = null
async function search(q) {
  controller?.abort()
  controller = new AbortController()
  const data = await fetch(`/api/search?q=${q}`, { signal: controller.signal })
}
```

**方案二：版本号，只处理最新请求的结果**
```js
let id = 0
async function search(q) {
  const reqId = ++id
  const data = await fetch(`/api/search?q=${q}`)
  if (reqId === id) render(data) // 只有最新请求才更新 UI
}
```

**方案三：防抖，合并短时间内多次调用**
```js
const debouncedSearch = debounce(search, 300)
```

## Q4：请求去重怎么实现？

用 Map 缓存正在进行的 Promise，相同请求复用同一个 Promise，请求完成后清除缓存。

```js
const pending = new Map()
function dedupedFetch(url) {
  const key = url
  if (pending.has(key)) return pending.get(key)
  const p = fetch(url).finally(() => pending.delete(key))
  pending.set(key, p)
  return p
}
```

关键：用 `.finally()` 在请求完成后清除缓存，保证下次请求是新的。

## Q5：重试机制的退避策略有哪些？为什么用指数退避？

三种退避策略：
- **固定间隔**：每次等 1s，简单但可能形成"惊群效应"
- **线性增长**：1s, 2s, 3s, 4s，渐进缓解
- **指数退避**：1s, 2s, 4s, 8s（推荐）

为什么用指数退避：多个客户端同时失败后同时重试，如果都用固定间隔，会在同一瞬间给服务端造成更大压力。指数退避让重试间隔逐渐增大，给服务端恢复时间。再加随机抖动（jitter）进一步分散。

## Q6：乐观锁和悲观锁分别适合什么场景？

**悲观锁**：操作前先加锁，防止干扰。适合写多、冲突频繁的场景（如库存扣减）。

**乐观锁**：不加锁，提交时检查版本号。适合读多写少、冲突少的场景（如文章编辑、用户资料修改）。

前端常见实现：请求携带版本号，后端校验版本号是否匹配。如果版本号已过期（409 Conflict），提示用户数据已被修改。

## Q7：Promise.race 和 Promise.any 的区别？

- `Promise.race`：第一个完成的（不管成功还是失败）
- `Promise.any`：第一个成功的（全部失败才失败）

```js
// race：超时控制
Promise.race([
  fetch('/api/data'),
  new Promise((_, reject) => setTimeout(() => reject('timeout'), 5000))
])

// any：多源取最快
Promise.any([
  fetch('/cdn1/api'),
  fetch('/cdn2/api'),
  fetch('/cdn3/api')
])
```

## Q8：前端怎么做 Mutex（互斥锁）？

用队列 + 标志位实现：locked 为 true 时，新请求放入队列等待；release 时唤醒队列中的下一个。

适用于防止并发写冲突的场景，比如：
- 余额扣减（防止并发扣减导致负数）
- 本地存储的读-改-写（防止数据覆盖）
- IndexedDB 事务串行化
