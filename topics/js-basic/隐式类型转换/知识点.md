# 隐式类型转换（== 规则）

## 核心概念

`==` 做隐式类型转换再比较，`===` 不转换，类型不同直接 false。

**实际开发原则**：除了 `== null` 这个惯用法，其他场景一律用 `===`。

## == 的转换规则（按优先级）

**1. null 和 undefined 特殊规定**
```js
null == undefined  // true（唯一相等的情况）
null == 0          // false
null == ''         // false
null == false      // false
```

**2. 有 NaN 直接 false**
```js
NaN == NaN  // false（NaN 不等于任何值包括自身）
```

**3. 布尔值先转数字**
```js
true == 1   // true，true → 1
false == 0  // true，false → 0
true == '1' // true，true → 1，'1' → 1
```

**4. 字符串 vs 数字 → 字符串转数字**
```js
1 == '1'   // true，'1' → 1
0 == ''    // true，'' → 0
0 == '0'   // true，'0' → 0
```

**5. 对象 vs 原始值 → 对象调用 valueOf/toString**
```js
[] == 0    // true，[] → '' → 0
[] == ''   // true，[] → ''
[1] == 1   // true，[1] → '1' → 1
{} == '[object Object]'  // true
```

## 常见追问

- `[] == ![]` 的结果是什么？
- 为什么 `null == 0` 是 false？
- `Object.is` 和 `===` 有什么区别？

## 回答要点

**`[] == ![]` 为 true 的推导**：
```
![] → false（[] 是真值，取反为 false）
[] == false
→ false 转数字：false → 0
→ [] == 0
→ [] 转原始值：[] → '' → 0
→ 0 == 0 → true
```

**`null == 0` 为 false**：null 只和 undefined 相等，不参与其他类型转换，这是规范的特殊规定。

**Object.is vs ===**：
```js
Object.is(NaN, NaN)  // true（=== 是 false）
Object.is(+0, -0)    // false（=== 是 true）
```
Object.is 是"同值相等"，比 === 更严格。

## 实用惯用法

```js
// 同时判断 null 和 undefined，用 == null
if (value == null) { ... }  // 等价于 value === null || value === undefined
```
