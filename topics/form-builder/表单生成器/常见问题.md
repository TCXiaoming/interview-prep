# 表单生成器 - 常见问题

## Q1：表单生成器的核心设计是什么？Schema 驱动是什么意思？

核心设计是 **Schema 驱动**：设计器产出一个 JSON Schema，渲染器消费这个 Schema 来动态渲染表单。两者完全解耦。

Schema 描述了表单的所有信息：字段列表、每个字段的类型、标签、校验规则、默认值、显隐条件等。

好处：
- Schema 可存储、传输、版本管理
- 不同端复用同一 Schema（PC、移动端、审批端渲染同一份 Schema）
- 设计器和渲染器可分别迭代

## Q2：Schema 怎么设计？需要包含哪些字段？

基础结构：

```json
{
  "formId": "唯一标识",
  "formName": "表单名称",
  "layout": "vertical/horizontal",
  "fields": [
    {
      "id": "字段唯一标识",
      "type": "组件类型（input/select/date...）",
      "label": "显示标签",
      "required": true/false,
      "props": "传给组件的额外属性",
      "rules": "校验规则数组",
      "defaultValue": "默认值",
      "condition": "条件显隐配置",
      "hidden": false
    }
  ]
}
```

关键设计：`type` 决定用哪个组件渲染，`props` 控制组件行为，`rules` 描述校验逻辑，`condition` 控制显隐联动。

## Q3：拖拽排序怎么实现的？

两种方案：

**原生 Drag & Drop**：组件面板 `dragstart` 设置数据，画布 `dragover` 计算插入位置，`drop` 时解析数据插入字段。

**基于库**：实际项目推荐用 Sortable.js / vuedraggable（Vue）/ dnd-kit（React），底层封装了原生 API，支持列表排序和跨列表拖拽，还处理了触摸设备兼容性。

核心是拖拽结束后更新 Schema 的 fields 数组顺序。

## Q4：渲染器怎么根据 Schema 动态渲染？

用**组件注册表**模式：维护一个 `type → 组件` 的映射表，渲染时根据 field.type 查找对应组件。

```js
const componentMap = {
  input: InputField,
  select: SelectField,
  date: DatePickerField,
  'user-picker': UserPickerComponent  // 业务组件
}

// 渲染时
<component :is="componentMap[field.type]" v-model="formData[field.id]" />
```

自定义组件通过 `register()` 方法注册到映射表中，不侵入核心逻辑。

## Q5：条件显隐怎么实现？

在 Schema 中定义字段的依赖关系：

```json
{
  "id": "sickNote",
  "condition": {
    "field": "leaveType",
    "operator": "eq",
    "value": "sick"
  }
}
```

渲染时遍历 fields，检查每个字段的 condition 是否满足，不满足的过滤掉。支持的操作符：eq（等于）、ne（不等于）、in（包含）、gt（大于）、lt（小于）。

## Q6：联动校验怎么做？

校验规则中引用其他字段的值：

```json
{
  "rules": [{
    "validator": "afterStart",
    "params": { "field": "startDate" },
    "message": "结束日期必须晚于开始日期"
  }]
}
```

校验时将整个 formData 传入校验函数，校验函数通过 `params.field` 取到依赖字段的值做比较。

## Q7：表单怎么和 bpmn-js 的流程节点绑定？

```
bpmn-js 节点（通过节点 id）←→ 表单 Schema（通过 formKey）
```

1. 在 bpmn-js 属性面板中点击「配置表单」
2. 弹出表单设计器，拖拽设计完成后保存
3. Schema 以 JSON 形式存储，节点通过 `formKey` 关联
4. 运行时根据当前审批节点的 `formKey` 加载对应 Schema

存储方式：流程结构存 BPMN XML，表单配置存 JSON，后端用节点 id 关联。

## Q8：设计器的状态管理怎么设计？

核心状态：

```js
const formDesigner = reactive({
  schema: { formId, formName, fields: [] },
  selectedFieldId: null,
  isDragging: false
})
```

操作方法：
- `addField(type, index)`：在指定位置插入新字段
- `removeField(id)`：删除字段
- `updateField(id, updates)`：更新字段属性（属性面板修改时调用）
- `moveField(from, to)`：拖拽排序

选中字段时，属性面板根据 `selectedFieldId` 找到对应字段，渲染其可编辑属性。

## Q9：大表单（50+ 字段）怎么优化性能？

1. **虚拟滚动**：只渲染可视区域内的字段
2. **分步渲染**：先渲染首屏字段，`requestIdleCallback` 渲染剩余字段
3. **懒加载**：复杂组件（富文本、上传）不在首屏的延迟加载
4. **Schema 精简**：默认属性不写入 Schema，渲染时合并默认值
5. **校验优化**：blur 时只校验单个字段，提交时才全量校验

## Q10：CPM 项目中表单生成器的核心难点是什么？

1. **设计器与 bpmn-js 的交互**：表单设计器以弹窗形式嵌入 bpmn-js 属性面板，需要处理好两个独立系统的状态同步——属性面板关闭后 bpmn-js 的流程图要更新 formKey
2. **业务组件接入**：审批人选择、部门选择等业务组件需要适配表单渲染器的组件注册表，同时要处理好异步数据加载
3. **流程变量联动**：表单字段的选项可能依赖流程上下文（如"审批人"选项取决于上一个节点的审批结果），需要渲染时从流程变量中动态获取
