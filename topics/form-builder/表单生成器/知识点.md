# 表单生成器

## 核心概念

表单生成器是一个通过可视化拖拽生成表单的工具，产出物是一个 JSON Schema 描述的表单配置。在 CPM 流程平台中，表单生成器负责定义每个审批节点需要填写的表单字段，审批人在审批时根据配置动态渲染表单。

核心流程：**设计表单（拖拽生成 Schema）→ 绑定到流程节点 → 运行时根据 Schema 动态渲染 → 收集数据提交**

---

## 1. 整体架构

```
表单生成器
├── 设计器（Designer）
│   ├── 组件面板（左侧）：可拖拽的表单组件列表
│   ├── 画布（中间）：预览和编辑表单布局
│   └── 属性面板（右侧）：编辑选中组件的属性
├── Schema（数据模型）
│   ├── 表单结构描述（字段、布局、校验规则）
│   └── 序列化为 JSON，存储到后端
├── 渲染器（Renderer）
│   └── 根据 Schema 运行时渲染表单
└── 校验器（Validator）
    └── 根据 Schema 中的校验规则验证数据
```

### 三层架构

```
Schema（数据）→ 渲染器（View）→ 用户交互 → 数据收集 → 提交
```

表单生成器的核心设计：**Schema 驱动**。设计器产出 Schema，渲染器消费 Schema，两套完全独立。这样做的好处是设计器和渲染器可以分别迭代，也可以在不同场景复用同一套 Schema。

---

## 2. Schema 设计

Schema 是表单生成器的核心产物，描述表单的字段、布局、校验规则、默认值等。

### 基础结构

```json
{
  "formId": "approval-form-001",
  "formName": "请假审批表单",
  "layout": "vertical",
  "fields": [
    {
      "id": "leaveType",
      "type": "select",
      "label": "请假类型",
      "required": true,
      "props": {
        "options": [
          { "label": "年假", "value": "annual" },
          { "label": "病假", "value": "sick" },
          { "label": "事假", "value": "personal" }
        ]
      },
      "rules": [
        { "required": true, "message": "请选择请假类型" }
      ]
    },
    {
      "id": "startDate",
      "type": "date",
      "label": "开始日期",
      "required": true,
      "rules": [
        { "required": true, "message": "请选择开始日期" }
      ]
    },
    {
      "id": "reason",
      "type": "textarea",
      "label": "请假原因",
      "props": {
        "maxLength": 500,
        "placeholder": "请输入请假原因"
      },
      "rules": [
        { "required": true, "message": "请输入请假原因" },
        { "max": 500, "message": "最多500字" }
      ]
    }
  ]
}
```

### Schema 设计要点

| 字段 | 说明 |
|------|------|
| `id` | 字段唯一标识，用于数据绑定和校验 |
| `type` | 组件类型，决定用哪个渲染组件 |
| `label` | 显示标签 |
| `required` | 是否必填（UI 标识） |
| `props` | 传给组件的额外属性（选项、placeholder 等） |
| `rules` | 校验规则数组 |
| `defaultValue` | 默认值 |
| `hidden` | 条件显隐 |
| `layout` | 字段在表单中的布局位置 |

### 与流程节点绑定

在 CPM 项目中，Schema 需要和 bpmn-js 的节点关联：

```json
{
  "nodeId": "UserTask_1",
  "formKey": "approval-form-001",
  "formConfig": { /* 上面的 Schema */ }
}
```

存储方式：JSON 独立存储（推荐），key 是节点 id。与 bpmn XML 分开，不侵入 BPMN 标准。

## 3. 拖拽实现

### 核心原理

```
组件面板（dragstart）→ 画布（dragover + drop）→ 解析 drop 位置 → 插入组件 → 更新 Schema
```

### 原生 Drag & Drop

```js
// 左侧面板：组件项
function onDragStart(e, componentType) {
  e.dataTransfer.setData('componentType', componentType)
  e.dataTransfer.effectAllowed = 'copy'
}

// 画布：接收拖拽
function onDragOver(e) {
  e.preventDefault()
  e.dataTransfer.dropEffect = 'copy'
  // 计算插入位置指示线
  updateDropIndicator(e.clientY)
}

function onDrop(e) {
  e.preventDefault()
  const type = e.dataTransfer.getData('componentType')
  const insertIndex = calcInsertIndex(e.clientY)
  addField(type, insertIndex) // 更新 Schema
}
```

### 基于库的方案

实际项目中推荐用成熟的拖拽库：
- **Sortable.js**：轻量，支持列表排序和跨列表拖拽
- **vuedraggable**：Vue 封装的 Sortable.js
- **dnd-kit**：React 生态的拖拽库

### 画布排序

组件拖入画布后，还需要支持在画布内拖拽排序：

```vue
<!-- Vue 示例：vuedraggable -->
<draggable
  v-model="formFields"
  group="form"
  item-key="id"
  handle=".drag-handle"
  @end="onSortEnd"
>
  <template #item="{ element }">
    <div class="form-field">
      <span class="drag-handle">⠿</span>
      <component :is="getComponent(element.type)" v-bind="element.props" />
      <span class="field-label">{{ element.label }}</span>
    </div>
  </template>
</draggable>
```

## 4. 渲染器

根据 Schema 动态渲染表单，是 Schema 的消费方。

### 核心思路

```vue
<template>
  <form @submit.prevent="handleSubmit">
    <template v-for="field in schema.fields" :key="field.id">
      <!-- 根据 type 动态选择组件 -->
      <component
        :is="componentMap[field.type]"
        v-model="formData[field.id]"
        v-bind="field.props"
        :label="field.label"
        :rules="field.rules"
      />
    </template>
    <button type="submit">提交</button>
  </form>
</template>

<script setup>
// 组件注册表
const componentMap = {
  input: InputField,
  textarea: TextareaField,
  select: SelectField,
  date: DatePickerField,
  radio: RadioField,
  checkbox: CheckboxField,
  number: NumberField,
  upload: UploadField
}

// 初始化表单数据（从 Schema 读取默认值）
const formData = ref({})
schema.fields.forEach(field => {
  formData.value[field.id] = field.defaultValue ?? getEmptyValue(field.type)
})
</script>
```

### 组件注册表模式

```js
// 组件注册表：type → 组件
const registry = {
  input: { component: Input, defaultProps: { placeholder: '请输入' } },
  textarea: { component: Textarea, defaultProps: { rows: 3 } },
  select: { component: Select, defaultProps: {} },
  date: { component: DatePicker, defaultProps: {} },
  radio: { component: RadioGroup, defaultProps: {} },
  checkbox: { component: CheckboxGroup, defaultProps: {} },
  number: { component: NumberInput, defaultProps: {} },
  upload: { component: FileUpload, defaultProps: {} },
  // 业务组件
  'user-picker': { component: UserPicker, defaultProps: {} },
  'dept-picker': { component: DeptPicker, defaultProps: {} },
  'form-ref': { component: FormReference, defaultProps: {} }
}

// 渲染时
function renderField(field) {
  const config = registry[field.type]
  if (!config) return null
  return {
    component: config.component,
    props: { ...config.defaultProps, ...field.props }
  }
}
```

### 支持自定义组件

业务场景需要自定义表单组件（如审批人选择、部门选择），通过注册表扩展：

```js
// 注册自定义组件
formRenderer.register('user-picker', {
  component: UserPickerComponent,
  defaultProps: { multiple: false },
  // 自定义数据序列化
  serialize: (value) => value?.userId,
  deserialize: (raw) => ({ userId: raw, userName: getUserName(raw) })
})
```

## 5. 校验体系

### Schema 驱动校验

```js
// 校验规则 Schema
const rules = [
  { required: true, message: '请输入姓名' },
  { min: 2, max: 20, message: '姓名长度2-20个字符' },
  { pattern: /^[\u4e00-\u9fa5]+$/, message: '姓名只能包含中文' },
  { validator: (value) => value !== 'admin', message: '不能使用admin' }
]

// 校验引擎
function validateField(value, rules) {
  for (const rule of rules) {
    if (rule.required && isEmpty(value)) {
      return rule.message
    }
    if (rule.min && String(value).length < rule.min) {
      return rule.message
    }
    if (rule.max && String(value).length > rule.max) {
      return rule.message
    }
    if (rule.pattern && !rule.pattern.test(value)) {
      return rule.message
    }
    if (rule.validator && !rule.validator(value)) {
      return rule.message
    }
  }
  return null // 校验通过
}

// 校验整个表单
function validateForm(formData, schema) {
  const errors = {}
  for (const field of schema.fields) {
    const error = validateField(formData[field.id], field.rules)
    if (error) {
      errors[field.id] = error
    }
  }
  return { valid: Object.keys(errors).length === 0, errors }
}
```

### 校验触发时机

| 时机 | 说明 |
|------|------|
| `blur` | 失焦时校验单个字段（推荐） |
| `change` | 值变化时校验（实时反馈，适合密码强度等） |
| `submit` | 提交时校验所有字段（兜底） |

### 联动校验

字段之间有依赖关系时需要联动校验：

```json
{
  "id": "endDate",
  "type": "date",
  "label": "结束日期",
  "rules": [
    { "required": true, "message": "请选择结束日期" },
    {
      "validator": "afterStart",
      "params": { "field": "startDate" },
      "message": "结束日期必须晚于开始日期"
    }
  ]
}
```

```js
// 联动校验执行
function validateWithDependencies(field, value, formData) {
  for (const rule of field.rules) {
    if (rule.validator === 'afterStart') {
      const startValue = formData[rule.params.field]
      if (value && startValue && new Date(value) <= new Date(startValue)) {
        return rule.message
      }
    }
  }
  return null
}
```

## 6. 条件显隐

表单字段根据其他字段的值动态显示/隐藏。

### Schema 设计

```json
{
  "id": "sickNote",
  "type": "upload",
  "label": "病假证明",
  "condition": {
    "field": "leaveType",
    "operator": "eq",
    "value": "sick"
  }
}
```

### 实现

```js
function isFieldVisible(field, formData) {
  if (!field.condition) return true

  const { field: depField, operator, value } = field.condition
  const depValue = formData[depField]

  switch (operator) {
    case 'eq': return depValue === value
    case 'ne': return depValue !== value
    case 'in': return value.includes(depValue)
    case 'gt': return depValue > value
    case 'lt': return depValue < value
    default: return true
  }
}

// 渲染时过滤
const visibleFields = computed(() =>
  schema.fields.filter(f => isFieldVisible(f, formData.value))
)
```

### CPM 中的场景

请假表单中：
- 选择「病假」→ 显示「病假证明上传」字段
- 选择「年假」→ 显示「剩余年假天数」字段
- 请假天数 > 3 天 → 显示「部门经理审批」节点的表单

## 7. 表单与流程节点绑定

在 CPM 项目中，表单需要绑定到 bpmn-js 的流程节点上。

### 绑定方式

```
bpmn-js 节点 ←(节点 id)→ 表单 Schema
```

1. 在 bpmn-js 的属性面板中选择「表单绑定」
2. 弹出表单选择/新建弹窗
3. 选择或创建表单 Schema
4. 将 `formKey` 写入节点的自定义属性

### 运行时数据流

```
审批人进入审批页 → 读取当前节点 id → 查找绑定的 formKey
→ 加载表单 Schema → 渲染器渲染表单 → 审批人填写
→ 校验 → 提交数据到后端 → 流程推进
```

### 不同节点不同表单

```
发起节点：请假申请表单（请假类型、日期、原因）
审批节点（部门经理）：审批表单（同意/驳回、意见）
审批节点（HR）：HR 审核表单（确认假期余额）
结束节点：无表单
```

每个节点通过 `formKey` 绑定不同的 Schema，运行时根据当前节点动态渲染。

## 8. 设计器实现

表单设计器是拖拽 + 属性编辑的可视化界面。

### 核心交互

```
左侧组件面板          中间画布                 右侧属性面板
┌──────────┐   ┌──────────────────┐   ┌──────────────┐
│ 输入框      │   │ 姓名 [________] │   │ 标签: 姓名     │
│ 文本域      │   │                  │   │ 必填: ☑       │
│ 下拉选择    │   │ 性别 ○男 ○女    │   │ placeholder: │
│ 日期选择    │   │                  │   │ ____________ │
│ 上传       │   │ 说明 [________] │   │ 校验规则:      │
│ ...        │   │                  │   │ 必填         │
└──────────┘   └──────────────────┘   └──────────────┘
  拖拽 → 画布       点击选中字段            编辑选中字段属性
```

### 状态管理

```js
// 表单设计器状态
const formDesigner = reactive({
  schema: {
    formId: generateId(),
    formName: '未命名表单',
    layout: 'vertical',
    fields: []
  },
  selectedFieldId: null,  // 当前选中的字段
  isDragging: false
})

// 操作
function addField(type, index) {
  const field = createDefaultField(type)
  formDesigner.schema.fields.splice(index, 0, field)
  formDesigner.selectedFieldId = field.id
}

function removeField(id) {
  const index = formDesigner.schema.fields.findIndex(f => f.id === id)
  formDesigner.schema.fields.splice(index, 1)
  if (formDesigner.selectedFieldId === id) {
    formDesigner.selectedFieldId = null
  }
}

function updateField(id, updates) {
  const field = formDesigner.schema.fields.find(f => f.id === id)
  Object.assign(field, updates)
}

function moveField(fromIndex, toIndex) {
  const [field] = formDesigner.schema.fields.splice(fromIndex, 1)
  formDesigner.schema.fields.splice(toIndex, 0, field)
}
```

### CPM 中的集成

表单设计器在 CPM 中以弹窗/抽屉的形式存在：

1. 在 bpmn-js 属性面板中点击「配置表单」
2. 弹出表单设计器弹窗，初始化已有 Schema（或空 Schema）
3. 拖拽设计完成后，点击保存
4. Schema 写入节点的 `formConfig`，保存到后端

## 10. 性能优化

### 大表单渲染

字段数量多（50+）时渲染卡顿：
- **虚拟滚动**：只渲染可视区域内的字段
- **分步渲染**：先渲染首屏字段，`requestIdleCallback` 渲染剩余字段
- **懒加载组件**：复杂组件（富文本、上传）不在首屏的延迟加载

### Schema 体积优化

- 不在 Schema 中存储冗余属性，只存必要字段
- 组件默认属性不写入 Schema，渲染时合并默认值

### 校验优化

- `blur` 时只校验单个字段，不校验整个表单
- 提交时才做全量校验
- 异步校验（如远程查重）用防抖

## 回答要点

### Schema 驱动的核心价值

设计器产出 Schema，渲染器消费 Schema，两者完全解耦。好处：
- Schema 可以存储、传输、版本管理
- 不同场景复用同一套 Schema（PC 端、移动端、审批端）
- 设计器和渲染器可以分别迭代，互不影响

### 表单与流程的关系

- **设计时**：在 bpmn-js 属性面板中为每个节点绑定表单 Schema
- **运行时**：根据当前审批节点加载对应的 Schema，渲染表单
- **数据流**：表单数据 → 校验通过 → 提交到后端 → 后端写入流程变量 → 流程推进

### 与 bpmn-js 集成的关键

表单 Schema 以 JSON 形式存储，与 BPMN XML 分开。节点通过 `formKey` 关联 Schema。保存时同时提交流程定义（XML）和表单配置（JSON），后端用节点 id 做关联。
