# AI 编程工具 — 常见面试题

## Q1: 介绍一下你在工作中使用 AI 编程工具的经验

**参考回答：**

我在工作中主要在三个层次使用 AI 工具：

第一层是代码补全，用 GitHub Copilot，日常写代码时它能自动补全重复性高的逻辑，比如类型定义、测试用例、API 调用模板。这个比较无感，就是打字快了。

第二层是问题排查和设计讨论，用 ChatGPT / Claude。比如遇到一个不熟悉的 API 或者报错，直接贴上去问，比查文档快。有时候也会用来讨论技术方案，让 AI 给几个选项，我来选。

第三层是项目级任务，用 Claude Code 这类 Agent 工具。比如批量重构、项目初始化、生成测试。它能读写文件、执行命令，端到端完成任务，不只是给代码片段。

但有一条红线：核心业务逻辑我不会直接用 AI 生成的代码，特别是鉴权、支付、数据校验这些。AI 生成的代码必须经过人工审查，边界条件和错误处理要重点看。

## Q2: AI 工具让你的开发效率提升了多少？有没有具体数据？

**参考回答：**

说实话这个很难精确量化，但我可以给几个体感：

写重复性代码的速度大概快了 50-60%，比如 CRUD 接口、类型定义、表单校验逻辑，Copilot 基本能一次补全。

排查问题的时间缩短了，以前查一个不熟悉的报错可能要翻 Stack Overflow、看官方文档，花 20-30 分钟，现在直接贴给 AI，5 分钟内能定位方向。但注意 AI 给的方案不一定对，需要验证。

但我发现一个反直觉的事：AI 让编码更快了，但 Review 的时间变长了。因为 AI 生成的代码风格可能不统一，错误处理可能不完善，我需要花更多时间审查。所以整体开发效率提升大概在 20-30%，没有编码阶段那么夸张。

## Q3: AI 生成的代码出过 bug 吗？你是怎么处理的？

**参考回答：**

出过。最典型的一次是 Copilot 生成了一个异步操作的代码，表面上逻辑没问题，但它默认用了 `try-catch` 包住整个函数，吞掉了所有异常，导致一个上游错误被静默忽略了。排查了半天才发现。

从那之后我定了几个规则：
1. AI 生成的错误处理代码必须人工 review，这是最容易出问题的地方
2. 所有 AI 生成的代码都要经过单元测试覆盖，特别是边界条件
3. TypeScript 类型要写严格，`strictNullChecks` 打开，让编译器帮忙兜底
4. 不熟悉领域的代码不用 AI 生成，比如加密、支付相关

说白了，AI 生成的代码是"初稿"，不是"终稿"。

## Q4: 你觉得未来前端工程师的核心竞争力是什么？

**参考回答：**

如果 AI 能写大部分 UI 代码，那前端工程师的价值要往上走：

第一，**复杂交互和用户体验的判断力**。AI 能写一个表单，但不知道这个表单在用户场景下该怎么设计交互流程、怎么处理异常状态、怎么做得流畅。这个需要人来判断。

第二，**架构设计能力**。系统怎么拆分、模块怎么组织、技术栈怎么选，这些决策 AI 做不了，因为它不了解团队的技术债务、业务的长期方向、人员的能力结构。

第三，**跨端和性能调优**。大疆的产品可能涉及 Web、移动端、嵌入式屏幕，跨端适配和性能优化需要实际的 profiling 经验，AI 在这方面帮不上太多。

第四，**工程化治理**。CI/CD 流程、代码规范、监控体系，这些是让团队高效协作的基础，不是写代码的问题。

所以我觉得核心竞争力从"写代码快"转向"做决策准"。

## Q5: 大疆的业务场景下，你觉得 AI 编程工具能怎么用？

**参考回答：**

大疆的前端场景可能覆盖几个方向：官网/App 的 Web 部分、后台管理系统、嵌入式设备的 UI 界面、还有可能有数据可视化大屏。

AI 工具在这些场景下的价值点不同：

后台管理系统 — AI 价值最大。CRUD 密集，模式固定，AI 生成初稿然后人工调整，效率提升明显。

数据可视化 — 可以用 AI 生成图表配置代码、数据转换逻辑，但视觉设计和交互优化需要人来做。

嵌入式 UI — 这个我不太了解大疆具体的技术栈，但如果是 Web 技术栈（比如用 Canvas/WebGL 渲染飞控界面），AI 在算法实现上能帮忙，但实时性和安全性要求高的部分需要人工把关。

总体思路是：在重复性高的场景用 AI 提效，在创新性和安全性要求高的场景靠人来把控。
