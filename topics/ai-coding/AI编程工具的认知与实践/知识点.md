# AI 编程工具的认知与实践

## 核心概念

### 主流 AI 编程工具分类

| 类别 | 代表工具 | 特点 |
|---|---|---|
| IDE 内嵌补全 | GitHub Copilot、Cursor、Tabnine | 实时代码补全，融入编码流程 |
| 对话式编程 | ChatGPT、Claude、通义灵码 | 问答驱动，适合设计讨论和问题排查 |
| Agent 型工具 | Claude Code、Cursor Composer、Devin | 自主执行多步骤任务，可读写文件、运行命令 |
| 专项工具 | v0（UI 生成）、Bolt、AI 插件开发 | 针对特定场景优化 |

### AI Coding 的能力边界

**擅长的场景：**
- 样板代码生成（CRUD、类型定义、配置文件）
- 已知模式的实现（排序算法、数据结构、常见设计模式）
- 代码转换与迁移（语言转换、框架迁移、API 升级）
- 测试用例生成
- 代码解释和文档生成
- 正则表达式、SQL 等非核心业务逻辑

**不擅长的场景：**
- 复杂业务逻辑的上下文理解（跨多个文件的业务流转）
- 架构级决策（需要理解团队历史、业务约束、长期演进方向）
- 性能优化（需要 profiling 数据和运行时上下文）
- 安全敏感代码（鉴权、加密、支付逻辑需要人工审核）
- 与内部系统/私有 API 的交互（缺乏上下文）

### 对研发流程的影响

```
传统流程：需求 → 设计 → 编码 → 自测 → Code Review → 上线
AI 辅助：需求 → 设计 → AI 生成初稿 → 人工修改 → 自测 → Code Review → 上线
                                  ↑
                            编码阶段被压缩，但 Review 阶段更重要
```

关键变化：
1. **编码时间缩短，但 Review 成本上升** — AI 生成的代码可能有隐蔽问题，需要更强的 Review 能力
2. **从"写代码"转向"审查代码"** — 开发者的角色从 author 变成 reviewer
3. **Prompt 工程成为新技能** — 如何准确描述需求、提供上下文决定了 AI 输出质量

## 常见追问

### Q: 你在实际项目中怎么用 AI 编程工具的？

**回答要点：**
- 具体说哪些场景用、哪些场景不用，不能泛泛而谈
- 举例：用 Copilot 做补全提速，用 Claude Code 做项目级重构和生成逐字稿，复杂业务逻辑自己写
- 强调 Review 机制：AI 生成的代码必须经过人工审查，特别是边界条件和错误处理

### Q: AI 会不会取代前端工程师？

**回答要点：**
- 短期不会。AI 擅长"已知模式的复现"，不擅长"未知问题的探索"
- 前端工程师的价值不只是写 UI，还包括：用户体验判断、性能调优、工程化治理、跨团队协调
- 角色会转变：从"代码生产者"变成"代码决策者 + 质量把关人"
- 类比：编译器没有取代程序员，AI 工具也不会，但会淘汰不会用 AI 工具的人

### Q: AI 生成的代码质量怎么保证？

**回答要点：**
1. **严格的 Code Review** — AI 代码和人工代码用同一套 Review 标准，甚至更严格
2. **类型约束** — TypeScript 类型定义越严格，AI 生成的代码越安全
3. **测试覆盖** — 对 AI 生成的代码优先补充单元测试，特别是边界条件
4. **Lint + 自动化** — ESLint 规则、husky pre-commit hook 作为兜底
5. **渐进式采用** — 先在非核心模块试用，验证质量后再推广到核心业务

### Q: 你对 AI Agent 型工具（如 Claude Code）怎么看？

**回答要点：**
- Agent 工具的优势：能读写文件、执行命令，端到端完成任务，不只是"给代码片段"
- 适合场景：项目初始化、批量重构、跨文件修改、生成测试
- 局限：上下文窗口有限，大项目需要合理拆分任务；无法真正"理解"业务意图
- 关键能力：如何给 Agent 足够的上下文（项目结构、规范、约束条件），而不是期望它自己猜

### Q: 如何评估一个 AI 工具是否值得引入团队？

**回答要点：**
1. **效率提升可量化** — 对比引入前后的开发速度（如 Copilot 的接受率、任务完成时间）
2. **质量不退化** — 引入后的 bug 率、线上问题数不能上升
3. **学习成本可控** — 团队成员能在 1-2 周内上手
4. **安全合规** — 代码不会被发送到不受信任的第三方服务器（金融行业尤其敏感）
5. **与现有流程兼容** — 不破坏现有的 CI/CD、Code Review 流程

## 回答要点总结

1. 用具体场景说明使用方式，不要说"我用 AI 提升了效率"这种空话
2. 强调人工审查的重要性 — 体现你对代码质量的把控意识
3. 认知要全面：既看到能力，也看到边界，不能极端（"AI 万能"或"AI 没用"）
4. 结合自己的项目经验举例，比如贷后自助服务平台中 AI 工具的实际应用
5. 大疆作为硬件公司，可以延伸讨论 AI 在嵌入式/IoT 前端开发中的应用场景
