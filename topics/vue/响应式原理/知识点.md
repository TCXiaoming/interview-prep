# Vue 响应式原理

## 核心概念

### Vue 2：Object.defineProperty

对已知属性逐个定义 getter/setter，在 getter 中收集依赖（Dep），在 setter 中触发更新。

**局限性**：
- 无法感知新增/删除属性 → 需要用 `Vue.set` / `Vue.delete`
- 无法感知数组索引赋值和 length 修改 → Vue 2 重写了数组的 7 个变异方法（push/pop/shift/unshift/splice/sort/reverse）

### Vue 3：Proxy

对整个对象创建代理，通过 trap 拦截所有操作：

```js
const proxy = new Proxy(target, {
  get(target, key, receiver) {
    track(target, key) // 收集依赖
    return Reflect.get(target, key, receiver)
  },
  set(target, key, value, receiver) {
    const result = Reflect.set(target, key, value, receiver)
    trigger(target, key) // 触发更新
    return result
  },
  deleteProperty(target, key) {
    const result = Reflect.deleteProperty(target, key)
    trigger(target, key)
    return result
  }
})
```

**为什么能感知新增属性**：`set` trap 拦截所有赋值操作，不管属性是否已存在，`obj.newKey = value` 同样会触发 `set`。

## 常见追问

- Proxy 有哪些 trap？
- Vue 3 为什么用 Reflect 配合 Proxy？
- reactive 对嵌套对象是怎么处理的？

## 回答要点

**常用 trap**：`get`（读取）、`set`（赋值）、`deleteProperty`（删除）、`has`（in 操作符）、`ownKeys`（Object.keys）

**为什么用 Reflect**：保证 `this` 指向正确，避免直接操作 target 时丢失 receiver 上下文

**嵌套对象**：reactive 是懒代理，访问嵌套对象时在 `get` trap 里判断返回值是否为对象，是则递归调用 `reactive` 包装，而不是初始化时递归处理所有层级

**set trap 如何区分新增/修改属性**：

```js
set(target, key, value, receiver) {
  const hadKey = key in target  // 或 Reflect.has(target, key)
  const result = Reflect.set(target, key, value, receiver)

  if (hadKey) {
    // 修改已有属性 → 触发该属性的依赖更新
    trigger(target, key, TriggerOpTypes.SET)
  } else {
    // 新增属性 → 触发整个对象的依赖更新
    trigger(target, key, TriggerOpTypes.ADD)
  }
  return result
}
```

这也是 Vue 3 不再需要 `Vue.set()` 的原因——Proxy 的 set trap 天然能拦截所有赋值操作，包括新增属性。
