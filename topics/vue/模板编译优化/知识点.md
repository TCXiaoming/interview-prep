# 模板编译优化

## 核心概念

Vue 3 编译器在生成 render 函数时做了两个关键优化：**静态提升**和 **PatchFlag**，两者解决不同层面的性能问题。

## 静态提升（hoistStatic）

把模板中**完全静态的节点**（无任何动态绑定）提取到 render 函数外部，组件每次重新渲染时复用同一个 vnode 对象，不重新创建。

```js
// 编译前（每次渲染都创建新 vnode）
function render() {
  return h('div', [
    h('span', 'static text'), // 静态节点，每次都新建
    h('span', dynamicText)    // 动态节点
  ])
}

// 编译后（静态节点提升到外部）
const hoisted = h('span', 'static text') // 只创建一次

function render() {
  return h('div', [
    hoisted,                  // 复用
    h('span', dynamicText)
  ])
}
```

**解决的问题**：减少 vnode 对象的创建开销。

## PatchFlag

对**动态节点**标记"哪部分是动态的"，diff 时只对比有标记的部分，跳过静态属性比较。

```html
<!-- 模板 -->
<span :class="cls">{{ text }}</span>

<!-- 编译后（伪代码） -->
h('span', { class: cls }, text, PatchFlags.CLASS | PatchFlags.TEXT)
// 标记：只有 class 和 text 是动态的
```

diff 时看到 PatchFlag，只比较 class 和 text，其他属性直接跳过。

**解决的问题**：减少 diff 比较开销。

## 两者对比

| | 静态提升 | PatchFlag |
|---|---|---|
| 作用对象 | 完全静态的节点 | 有动态绑定的节点 |
| 优化阶段 | 减少 vnode 创建 | 减少 diff 比较 |
| 标记方式 | 提到 render 函数外 | 编译时加数字标记 |

## 常见追问

- 静态提升会提升哪些内容？
- PatchFlag 有哪些类型？
- Vue 3 还有哪些编译优化？

## 回答要点

**还有一个优化——Block Tree**：动态节点会被收集到最近的 Block 节点的 dynamicChildren 数组里，diff 时直接遍历 dynamicChildren，跳过静态子树，进一步减少 diff 范围。

三个优化合在一起：静态提升（少建对象）+ PatchFlag（少比较属性）+ Block Tree（少遍历节点）= Vue 3 比 Vue 2 快的核心原因。
