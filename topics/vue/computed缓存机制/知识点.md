# computed 缓存机制

## 核心概念

computed 基于响应式系统实现，核心是 **dirty 标志位**控制缓存有效性。

## dirty 标志位机制

```js
function computed(getter) {
  let dirty = true  // 初始为 true，表示需要重新计算
  let value

  const effect = new ReactiveEffect(getter, () => {
    // 依赖变化时的调度器：只把 dirty 置为 true，不立即重新计算
    if (!dirty) {
      dirty = true
    }
  })

  return {
    get value() {
      if (dirty) {
        dirty = false
        value = effect.run() // 执行 getter，同时收集依赖
      }
      return value // dirty 为 false 时直接返回缓存
    }
  }
}
```

**执行流程**：
1. 首次访问：`dirty = true` → 执行 getter，收集依赖，缓存结果，`dirty = false`
2. 再次访问：`dirty = false` → 直接返回缓存值
3. 依赖变化：调度器触发，`dirty = true` → 下次访问重新计算

## 常见追问

- computed 是懒执行的吗？
- computed 和 watch 有什么区别？
- computed 可以有 setter 吗？

## 回答要点

**懒执行**：computed 是懒的，只有被访问时才执行 getter，不访问不计算。watch 是立即订阅的（watchEffect 初始化就执行）。

**computed vs watch**：
- computed：有返回值，适合派生数据，有缓存
- watch：无返回值，适合执行副作用（请求、操作 DOM），可拿新旧值

**computed setter**：
```js
const fullName = computed({
  get: () => firstName.value + ' ' + lastName.value,
  set: (val) => {
    [firstName.value, lastName.value] = val.split(' ')
  }
})
```
