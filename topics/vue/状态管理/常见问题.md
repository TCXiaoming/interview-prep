# Vue 状态管理 常见问题

### Q: 从 Vuex 迁移到 Pinia 需要改什么？

**回答要点：**
- state → setup store 中的 `ref()` / `reactive()`
- getters → `computed()`
- mutations → 删除，直接在 actions 中修改 state
- actions → setup store 中的普通函数
- modules → 拆分为独立的 `defineStore`
- `mapState` / `mapActions` → 组件中直接用 hooks

### Q: storeToRefs 的作用是什么？

**回答要点：**
类似 `toRefs`，但专门为 Pinia store 做了优化。因为 store 本身是一个 reactive 对象，直接解构会丢失响应式。`storeToRefs` 只提取 state 和 getters（跳过 actions），保持响应式连接。

### Q: 一个页面上多个组件都用了同一个 store，store 是同一个实例吗？

**回答要点：**
是的。`useXxxStore()` 返回的是同一个单例。Pinia 内部用 `map` 缓存 store 实例，key 是 `defineStore` 的第一个参数（store id）。组件销毁时不会删除 store 实例，除非显式调用 `store.$reset()`。

### Q: 什么时候用 Pinia 的 options store 而不是 setup store？

**回答要点：**
- 从 Vuex 迁移过来的老项目，options store 结构类似 Vuex，迁移成本低
- 不需要 Composition API 特性的简单 store
- 新项目推荐统一用 setup store（更灵活、TS 推导更好）

### Q: 状态管理和 provide/inject 怎么选？

**回答要点：**
- provide/inject：父子组件间共享，不需跨路由传递
- Pinia：全局共享，跨组件/跨路由/跨页面
- 两者可以共存：provide/inject 做局部状态，Pinia 做全局状态
