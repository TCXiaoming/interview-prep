# Vue vs React 核心对比

## 1. 响应式机制


|          | Vue                    | React                                        |
| -------- | ---------------------- | -------------------------------------------- |
| **依赖追踪** | 自动精确追踪（Proxy）          | 无自动追踪，全树 diff                                |
| **更新粒度** | 组件级，用到数据的组件才重渲染        | 组件级，但默认子组件也重渲染                               |
| **优化方式** | 开箱即用，无需手动优化            | 需要 `React.memo`、`useMemo`、`useCallback` 手动优化 |
| **状态定义** | `ref()` / `reactive()` | `useState()` / `useReducer()`                |
| **状态访问** | ref 需要 `.value`（JS 中）  | 直接访问 `state` / `setState`                    |


**Vue 侧**：Proxy 拦截 get/set，getter 中 `track` 收集依赖，setter 中 `trigger` 触发更新。只有依赖了该数据的组件才重新渲染。

**React 侧**：`useState` 返回 `[state, setState]`，setState 触发全树 diff。默认不追踪哪个组件用了哪些数据，需要手动用 `React.memo` 包裹子组件、`useMemo` 缓存计算、`useCallback` 稳定函数引用。

**面试话术**：Vue 的响应式是"订阅-通知"模式，精确知道谁变了、谁依赖了；React 是"重新计算"模式，不知道谁变了，所以默认全树 diff，靠开发者手动告诉它哪里不用算。

---

## 2. 组件更新触发


|             | Vue                   | React                               |
| ----------- | --------------------- | ----------------------------------- |
| **触发条件**    | 响应式数据变化自动触发           | 调用 `setState` / `useState` 的 setter |
| **批量更新**    | `nextTick`（微任务）合并     | `setState` 自动批处理（React 18 全场景）      |
| **更新机制**    | 同步 diff + nextTick 批量 | Fiber 时间切片，可中断                      |
| **this 问题** | 无（Composition API）    | Class 组件有 this 绑定问题                 |


**Vue 侧**：响应式数据变化 → 触发依赖的组件重新渲染 → `nextTick` 批量合并同一 tick 内的多次更新。

**React 侧**：

- React 17：事件处理函数内 `setState` 会批量合并，但 `setTimeout`、`Promise` 回调内不会
- React 18：所有场景都自动批处理（包括 `setTimeout`、`Promise`），不需要手动合并

**相关知识点**：`topics/vue/computed缓存机制/`、`topics/react/React18自动批处理/`

## 3. 状态管理对比


|           | Vue                         | React                               |
| --------- | --------------------------- | ----------------------------------- |
| **基本类型**  | `ref(0)`                    | `useState(0)`                       |
| **对象/数组** | `reactive({})`              | `useState({})`                      |
| **派生数据**  | `computed()`                | `useMemo()`                         |
| **副作用**   | `watch()` / `watchEffect()` | `useEffect()` / `useLayoutEffect()` |
| **更新方式**  | 直接修改 `state.value = x`      | 必须调 `setState(x)`，不可直接修改            |


### ref vs useState

```js
// Vue
const count = ref(0)
count.value++  // 直接修改

// React
const [count, setCount] = useState(0)
setCount(count + 1)  // 必须通过 setter，不直接修改
```

### computed vs useMemo

```js
// Vue：computed 有缓存，依赖不变返回缓存
const doubled = computed(() => count.value * 2)

// React：useMemo 有缓存，依赖不变返回缓存
const doubled = useMemo(() => count * 2, [count])
```

两者实现原理相似：Vue 用 dirty 标志位，React 用依赖数组比较。都是懒执行 + 缓存。

**相关知识点**：`topics/vue/ref与reactive/`、`topics/vue/computed缓存机制/`、`topics/react/useMemo与useCallback/`

## 4. 组件通信


|          | Vue                    | React                   |
| -------- | ---------------------- | ----------------------- |
| **父→子**  | `props`                | `props`                 |
| **子→父**  | `emit` / `v-model`     | 回调函数 `props.onXxx`      |
| **跨层级**  | `provide/inject`       | `Context`               |
| **全局状态** | Pinia / Vuex           | Redux / Zustand / Jotai |
| **事件总线** | Vue 3 已移除 `$on`，用 mitt | 没有内置，用第三方库              |


### 子→父通信对比

```vue
<!-- Vue：emit 事件 -->
<!-- 父组件 -->
<Child @update="handleUpdate" />
<!-- 子组件 -->
<button @click="$emit('update', value)">Submit</button>
```

```jsx
// React：回调函数
// 父组件
<Child onUpdate={handleUpdate} />
// 子组件
<button onClick={() => onUpdate(value)}>Submit</button>
```

本质相同，Vue 用 emit 语法糖，React 直接传函数。

### 跨层级通信对比

```js
// Vue：provide / inject
// 祖先组件
provide('theme', 'dark')
// 后代组件
const theme = inject('theme') // 响应式

// React：Context
const ThemeContext = createContext('light')
// 祖先
<ThemeContext.Provider value="dark">
// 后代
const theme = useContext(ThemeContext)
```

Vue 的 provide/inject 保持响应式；React 的 Context 值变化会导致所有消费者重渲染。

## 5. 组件复用模式


|           | Vue             | React                   |
| --------- | --------------- | ----------------------- |
| **逻辑复用**  | Composables（函数） | Custom Hooks（函数）        |
| **UI 复用** | Slots（插槽）       | Children / Render Props |
| **继承**    | mixins（不推荐）     | HOC（高阶组件，逐渐减少）          |


### Composables vs Custom Hooks

```js
// Vue Composable
function useMouse() {
  const x = ref(0)
  const y = ref(0)
  window.addEventListener('mousemove', e => {
    x.value = e.clientX
    y.value = e.clientY
  })
  return { x, y }
}

// React Custom Hook
function useMouse() {
  const [x, setX] = useState(0)
  const [y, setY] = useState(0)
  useEffect(() => {
    const handler = e => { setX(e.clientX); setY(e.clientY) }
    window.addEventListener('mousemove', handler)
    return () => window.removeEventListener('mousemove', handler)
  }, [])
  return { x, y }
}
```

结构几乎一样，区别在于：Vue 的 ref 直接修改即可触发更新，React 必须调 setState + useEffect 管理副作用和清理。

**相关知识点**：`topics/react/useCallback使用场景/`、`topics/react/useEffect与useLayoutEffect/`

## 6. 模板 vs JSX


|          | Vue（模板）                 | React（JSX）                |
| -------- | ----------------------- | ------------------------- |
| **编写方式** | Template + 指令           | JSX + JavaScript          |
| **编译优化** | 编译时静态分析（PatchFlag、静态提升） | 运行时 diff，无编译优化            |
| **条件渲染** | `v-if` / `v-show`       | `{condition && <Comp />}` |
| **列表渲染** | `v-for`                 | `.map()`                  |
| **灵活性**  | 受限于模板语法                 | 完全的 JavaScript 能力         |


### 条件渲染对比

```vue
<!-- Vue -->
<div v-if="show">显示</div>
<div v-show="show">显示（DOM 保留）</div>
```

```jsx
// React
{show && <div>显示</div>}
<div style={{ display: show ? 'block' : 'none' }}>显示（DOM 保留）</div>
```

### 编译优化差异

Vue 3 模板可以在编译时做静态分析：

- **静态提升**：静态节点提到 render 函数外，不重复创建
- **PatchFlag**：标记动态节点的哪部分变了，diff 时只比较有标记的部分
- **Block Tree**：收集动态节点，diff 只遍历动态子树

React JSX 在编译时无法做这类优化（JSX 本质是 `React.createElement()` 调用，编译器不知道哪些是静态的）。

**相关知识点**：`topics/vue/模板编译优化/`

## 7. Diff 算法与渲染


|             | Vue                          | React                  |
| ----------- | ---------------------------- | ---------------------- |
| **Diff 粒度** | 双端 diff + 最长递增子序列          | Fiber 链表遍历             |
| **Diff 方式** | 单次同步完成                       | 时间切片，可中断               |
| **调度机制** | nextTick 微任务批量              | MessageChannel + 优先级调度 |
| **性能瓶颈** | 大数据量单次 diff 阻塞              | 默认全树 diff 开销大，需手动优化    |
| **时间复杂度** | O(n)（双端跳过 + LIS 最多 O(nlogn)） | O(n)（单次遍历，但全树）         |
| **空间复杂度** | O(n)（key → index 映射表）        | O(n)（Fiber 树 + 链表指针）   |
| **DOM 移动优化** | 最长递增子序列，最小化移动次数          | 仅靠 key 匹配，无 LIS 优化     |


### Vue Diff

Vue 的 diff 算法（双端比较 + 最长递增子序列）：

1. **双端比较**：新旧子节点各设头尾指针，从两端向中间逼近
   - 旧头 vs 新头：相同则双指针右移，跳过
   - 旧尾 vs 新尾：相同则双指针左移，跳过
   - 旧头 vs 新尾 / 旧尾 vs 新头：交叉匹配
   - 以上都不匹配：用 key 在旧节点中查找
   - 最优情况下（节点只在头部或尾部增删），时间复杂度接近 **O(1)**
2. **中间乱序部分**：建 key → index 映射表，找出新节点在旧节点中的位置
3. **最长递增子序列（LIS）**：在乱序部分中找到不需要移动的节点集合（时间复杂度 O(n log n)），只移动不在 LIS 中的节点

总时间复杂度：双端比较 O(min(m,n)) + 中间部分 O(n) + LIS O(n log n) = **O(n log n)** 最坏情况。实际场景中双端匹配能跳过大量节点，通常接近 **O(n)**。

**DOM 操作最小化**：LIS 确保只移动真正需要移动的节点，不移动的节点保持不动。

```js
// 简化示意
// 旧：[A, B, C, D, E, F]
// 新：[A, C, B, E, D, F]
// 双端比较：A（头匹配）、F（尾匹配）→ 跳过
// 中间：[B, C, D, E] vs [C, B, E, D]
// LIS：[B, E] 或 [C, E]（最长递增子序列）
// 只需移动 C 和 D，B 和 E 不动
```

### React Diff

React Fiber 的 diff：

1. **单向遍历**：从第一个子节点开始，逐个对比新旧 Fiber 节点
   - type 相同 + key 相同：复用 Fiber 节点，更新 props
   - type 不同 或 key 不同：标记旧节点为删除，创建新节点
   - 遇到 key 不匹配的节点：从当前位置开始，把剩余旧节点全部放入 `map`，然后逐个查找
2. **无 LIS 优化**：React 不找最长递增子序列，节点位置变了就移动（或删除重建）
3. **时间切片**：遍历过程可中断，一帧内算不完就暂停

总时间复杂度：**O(n)**（单次遍历所有子节点）。但因为没有 LIS 优化，DOM 移动次数可能多于 Vue。

```js
// 同样的例子
// 旧：[A, B, C, D, E, F]
// 新：[A, C, B, E, D, F]
// React diff：
// A 匹配 → 复用
// B vs C → key 不同，B 标记删除，C 标记新增
// B vs B → 后面找到 B，复用但移动位置
// ...依此类推
// 可能触发的 DOM 移动次数多于 Vue
```

**React 为什么不做 LIS**：Fiber 的时间切片设计要求每一步操作都足够小，LIS 算法需要遍历完所有节点才能计算，不适合拆分到多个时间切片中。React 选择"快速完成 diff + 稍多的 DOM 操作"换取"可中断的流畅交互"。

**面试话术**：Vue 的 diff 复杂度上限是 O(n log n)（含 LIS），但实际双端比较能跳过大量节点，通常接近 O(n)，且 DOM 移动次数最少。React 的 diff 是 O(n)（单次遍历），但没有 LIS 优化，DOM 移动次数可能更多。Vue 是"算得更聪明、移动更少"，React 是"算得更快、可中断"。两者都是线性复杂度级别，差异主要在 DOM 操作次数和可中断性上。

**相关知识点**：`topics/vue/模板编译优化/`、`topics/react/Fiber架构/`、`topics/react/Vue与React性能差异/`

## 8. 事件系统


|          | Vue                                         | React                    |
| -------- | ------------------------------------------- | ------------------------ |
| **事件绑定** | `@click` / `v-on`                           | `onClick`（合成事件）          |
| **事件委托** | 不自动委托，直接绑到元素                                | 统一委托到根容器                 |
| **原生事件** | `@click.native`（Vue 2）/ `useRef` 直接绑（Vue 3） | `ref.addEventListener()` |
| **跨浏览器** | 不封装，依赖浏览器                                   | 合成事件统一差异                 |


### 事件绑定对比

```vue
<!-- Vue：直接绑定到元素 -->
<button @click="handleClick">Click</button>
<!-- 原生事件直接在 DOM 上 -->
```

```jsx
// React：合成事件，委托到根容器
<button onClick={handleClick}>Click</button>
// 实际绑在根容器 div 上，通过事件冒泡捕获
```

Vue 的事件处理函数在每次渲染时引用稳定（不需要 useCallback）；React 的内联函数每次渲染都是新引用，配合 `React.memo` 时需要 `useCallback`。

**相关知识点**：`topics/react/合成事件/`、`topics/react/useCallback使用场景/`

## 9. 生命周期对比


| Vue 3 (Composition API) | React (Hooks)                                   | 说明          |
| ----------------------- | ----------------------------------------------- | ----------- |
| `onMounted`             | `useEffect(() => {}, [])`                       | 组件挂载后       |
| `onUpdated`             | `useEffect(() => {})` 每次渲染后                     | 组件更新后       |
| `onUnmounted`           | `useEffect(() => { return () => {} }, [])` 清理函数 | 组件销毁前       |
| `onBeforeMount`         | -                                               | React 无直接对应 |
| `onBeforeUpdate`        | `useLayoutEffect`                               | DOM 更新前     |
| `watch`                 | `useEffect(() => {}, [dep])`                    | 依赖变化时       |
| `watchEffect`           | `useEffect(() => {})`（无依赖数组）                    | 自动追踪依赖      |


### 关键差异

Vue 的 `onMounted` 是同步执行（DOM 挂载后立即调用）；React 的 `useEffect` 是异步执行（浏览器绘制后）。

Vue 的 `watch` 可以拿新旧值；React 的 `useEffect` 只能拿当前值，旧值需要自己用 ref 缓存。

```js
// React 拿旧值的写法
const prevCount = useRef()
useEffect(() => {
  console.log('旧值:', prevCount.current)
  console.log('新值:', count)
  prevCount.current = count
}, [count])
```

**相关知识点**：`topics/react/useEffect与useLayoutEffect/`

## 10. 性能优化策略对比


|           | Vue                       | React                 |
| --------- | ------------------------- | --------------------- |
| **默认行为**  | 精确追踪，开箱即用                 | 全树 diff，需手动优化         |
| **子组件优化** | 自动（响应式系统）                 | `React.memo`          |
| **计算缓存**  | `computed`（自动）            | `useMemo`（手动）         |
| **函数稳定**  | 不需要（模板中引用稳定）              | `useCallback`（手动）     |
| **大列表**   | 虚拟滚动库                     | 虚拟滚动库（react-window 等） |
| **编译优化**  | PatchFlag、静态提升、Block Tree | 无（JSX 是运行时）           |


### React 优化三件套

```jsx
// 1. React.memo：子组件不必要重渲染
const Child = React.memo(({ data, onClick }) => { ... })

// 2. useMemo：缓存计算结果
const sorted = useMemo(() => items.sort(compare), [items])

// 3. useCallback：稳定函数引用
const handleClick = useCallback(() => { ... }, [deps])
```

### Vue 不需要这些

Vue 的响应式系统自动追踪依赖：

- 子组件只依赖 `props.count`，`props.name` 变了不会重渲染 → 不需要 memo
- `computed` 自动缓存 → 不需要 useMemo
- 模板中的函数引用稳定 → 不需要 useCallback

**面试话术**：React 把优化的决定权交给开发者（更灵活但心智负担高），Vue 把优化自动化（更省心但在极端场景灵活性不如 React）。

**相关知识点**：`topics/react/useMemo与useCallback/`、`topics/react/useCallback使用场景/`、`topics/vue/computed缓存机制/`

## 11. 选型总结


| 维度       | Vue 更适合        | React 更适合        |
| -------- | -------------- | ---------------- |
| **团队背景** | 后端转前端、初级开发者    | 有函数式编程背景         |
| **项目规模** | 中小型项目，快速迭代     | 大型项目，长期维护        |
| **性能需求** | 中等数据量，开箱即用     | 超大数据量，需要精细调度     |
| **生态需求** | 国内生态丰富         | 全球生态最广           |
| **学习成本** | 低（模板语法直观）      | 中高（Hooks 心智模型）   |
| **类型支持** | Vue 3 + TS 支持好 | React + TS 生态更成熟 |


**面试话术**：没有绝对的好坏。Vue 的优势是开发效率高、上手快、默认性能好；React 的优势是生态广、灵活性高、大数据调度能力强。选型看团队和业务场景。
