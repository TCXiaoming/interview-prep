# Vue vs React - 常见问题

## Q1：Vue 和 React 的核心区别是什么？

从三个层面回答：

1. **响应式机制**：Vue 用 Proxy 自动追踪依赖，精确知道谁变了；React 不追踪，全树 diff，默认每个组件都重跑
2. **更新调度**：Vue 同步 diff + nextTick 批量；React Fiber 时间切片，可中断，不阻塞用户交互
3. **优化策略**：Vue 开箱即用（自动精确）；React 靠开发者手动优化（memo、useMemo、useCallback）

一句话总结：Vue 是"订阅-通知"模式，React 是"重新计算"模式。

## Q2：Vue 的 computed 和 React 的 useMemo 有什么区别？

功能类似，都是缓存派生数据，但：

| | Vue computed | React useMemo |
|---|---|---|
| 缓存机制 | dirty 标志位，依赖变时 dirty=true，访问时才重算 | 依赖数组浅比较，变了就重算 |
| 使用频率 | 高频使用，是 Vue 的标配 | 谨慎使用，过度使用反而有开销 |
| 语法 | `computed(() => ...)` | `useMemo(() => [...])` |
| 类型 | 响应式对象 | 普通值（非响应式） |

Vue 的 computed 用起来更自然（到处都是）；React 的 useMemo 要手动判断哪些值得缓存。

## Q3：为什么 React 需要 useCallback，Vue 不需要？

React 组件每次重渲染时，函数定义都会重新执行，产生新的函数引用。如果传给 `React.memo` 包裹的子组件，引用变了会导致 memo 失效（props 比较发现不同）。

Vue 的模板中，事件处理函数的引用是稳定的——模板编译后，函数绑定在组件实例上，重渲染不会产生新引用。所以 Vue 不需要类似 useCallback 的东西。

## Q4：Vue 的 v-if 和 React 的条件渲染有什么区别？

```vue
<!-- Vue -->
<div v-if="show">内容</div>
<div v-else>替代内容</div>
```

```jsx
// React
{show ? <div>内容</div> : <div>替代内容</div>}
// 或
{show && <div>内容</div>}
```

Vue 的 `v-if` 有编译优化：条件为 false 时不会创建 vnode。React 的条件渲染是 JavaScript 表达式，每次都要执行求值。

另外 Vue 还有 `v-show`（DOM 保留，display 切换），React 没有直接对应，需要手动写 `style={{ display }}`。

## Q5：Vue 的 provide/inject 和 React 的 Context 有什么区别？

两者都用于跨层级通信，但：

- Vue 的 provide/inject 保持响应式——provide 的值变化，inject 的组件自动更新
- React 的 Context 值变化，所有消费者组件都会重渲染（无法精确知道哪部分变了）
- Vue 的 provide/inject 性能更好，因为它走的是响应式系统，精确通知
- React 的 Context 适合不频繁变化的值（主题、语言等），高频变化的值不适合用 Context

## Q6：Vue 3 的模板编译优化，React 能做到吗？

做不到。原因是 JSX 本质是 `React.createElement()` 的语法糖，编译器看到的是一堆函数调用，无法在编译时分析哪些是静态的、哪些是动态的。

Vue 的 `.vue` 模板是静态的 HTML-like 语法，编译器可以：
- 分析每个节点哪些属性是动态的 → PatchFlag
- 把完全静态的节点提升到 render 函数外 → 静态提升
- 收集动态节点到 Block 的 dynamicChildren → Block Tree

React 要实现类似优化，需要靠运行时（如 `React.memo`、`useMemo`），开发者手动告诉 React 哪些不用算。

## Q7：Vue 和 React 的 Diff 算法有什么区别？

**Vue**：双端比较 + 最长递增子序列
- 头尾指针向中间逼近，跳过未变化的节点
- 剩余节点建 key → index 映射
- 找最长递增子序列，只移动不在序列中的节点（最小化 DOM 移动）
- 同步执行，一次性算完

**React**：Fiber 链表遍历
- 逐个 Fiber 节点对比新旧 props
- 时间切片：一帧内算不完就暂停，让出主线程
- 不做最长递增子序列优化，靠 key 判断节点是否移动

Vue 的 diff 策略更"聪明"（最小化 DOM 操作），React 的 diff 更"可控"（不阻塞交互）。

## Q7.5：Vue 和 React 的 Diff 算法时间复杂度分别是多少？

两者都是线性级别，但细节不同：

| | Vue | React |
|---|---|---|
| **最坏时间复杂度** | O(n log n)（含 LIS 计算） | O(n)（单次遍历） |
| **实际时间复杂度** | 接近 O(n)（双端比较跳过大量节点） | O(n)（全树遍历） |
| **空间复杂度** | O(n)（key→index 映射表） | O(n)（Fiber 树 + 指针） |
| **DOM 移动次数** | 最少（LIS 优化） | 可能更多（无 LIS） |
| **可中断性** | 不可中断 | 可中断（时间切片） |

Vue 的 O(n log n) 是因为最长递增子序列算法，但双端比较阶段能跳过大量匹配节点，实际中很少触发 LIS 部分，所以通常接近 O(n)。

React 选择不做 LIS 是因为 LIS 需要遍历完所有节点才能计算，不适合拆分到多个时间切片中。React 用"稍多的 DOM 操作"换取"可中断的流畅交互"。

**面试话术**：两者都是线性复杂度级别，差异不在算法复杂度上，而在 DOM 操作次数和可中断性上——Vue 移动更少但不可中断，React 移动可能更多但不阻塞交互。

## Q8：你项目里 Vue 3 和 React 都用过，实际开发体验有什么不同？

可以从以下角度回答（结合自身经历）：

1. **上手速度**：Vue 模板语法对后端转前端的同事更友好，React 的 Hooks 心智模型需要适应
2. **代码组织**：Vue Composition API 按逻辑功能组织代码，React Hooks 也是类似的思路，但 useEffect 的依赖数组容易出 bug
3. **TypeScript**：Vue 3 + TS 支持不错，但模板内的类型推导不如 React JSX 直接（模板是字符串，JSX 是 JS）
4. **调试**：React DevTools 能看到每个组件为什么重渲染（Profiler），Vue DevTools 更直观展示响应式依赖
5. **生态**：React 的组件库和工具链更丰富（全球视角），Vue 在国内生态更成熟
