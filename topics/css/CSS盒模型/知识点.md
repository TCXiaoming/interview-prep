# CSS 盒模型

## 核心概念

每个元素都是一个盒子，由四层组成（从内到外）：
**content → padding → border → margin**

`box-sizing` 控制 `width/height` 的计算范围：

| | content-box（默认） | border-box |
|---|---|---|
| width 包含 | 只有 content | content + padding + border |
| 实际占用宽度 | width + padding + border | width（就是设置的值） |
| margin | 不算进去 | 不算进去 |

**关键记忆**：`margin` 永远不算进 `width`，两种模式都一样。

```css
/* content-box：设 width:200px，实际占 200+20+2=222px */
.box {
  box-sizing: content-box;
  width: 200px;
  padding: 10px;
  border: 1px solid;
}

/* border-box：设 width:200px，实际占 200px，内容区被压缩到 178px */
.box {
  box-sizing: border-box;
  width: 200px;
  padding: 10px;
  border: 1px solid;
}
```

## 常见追问

- 为什么现代项目通常全局设置 `box-sizing: border-box`？
- margin 塌陷是什么？
- `outline` 和 `border` 有什么区别？

## 回答要点

**为什么用 border-box**：布局时设置 `width: 50%`，如果是 `content-box`，加上 padding 和 border 后实际宽度会超过 50%，导致布局错乱。`border-box` 让 width 就是最终占用宽度，更直觉、更好控制。

现代项目通常全局重置：
```css
*, *::before, *::after {
  box-sizing: border-box;
}
```

**margin 塌陷**：相邻块级元素的垂直 margin 会合并，取较大值而不是相加。父子元素之间也会发生（子元素的 margin-top 会"穿透"到父元素）。触发 BFC 可以解决。

**outline vs border**：`outline` 不占用空间（不影响布局），`border` 占用空间。`outline` 常用于 focus 状态的视觉反馈。
