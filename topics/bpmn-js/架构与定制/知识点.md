# bpmn-js 架构与定制

## 核心概念

bpmn-js 是一个基于 BPMN 2.0 标准的流程图编辑器，底层基于 diagram-js（画布引擎）和 bpmn-moddle（BPMN 数据模型）。它提供了流程图的可视化编辑能力，但开箱即用的样式和交互与实际业务需求通常差距较大，需要深度定制。

---

## 1. 整体架构

```
bpmn-js
├── diagram-js        # 画布引擎（拖拽、缩放、选区、事件）
│   ├── canvas        # 画布管理（缩放、平移、视口）
│   ├── element-registry # 元素注册表
│   ├── event-bus     # 事件总线
│   ├── command-stack  # 命令栈（撤销/重做）
│   ├── modeling       # 建模操作（增删改节点）
│   └── selection      # 选区管理
├── bpmn-moddle       # BPMN 数据模型（解析/序列化 XML）
└── bpmn-js 业务层
    ├── bpmn-rules    # 规则引擎（什么能拖到哪）
    ├── bpmn-renderer # 节点渲染
    ├── bpmn-palette  # 左侧工具栏
    └── properties-panel # 右侧属性面板
```

### 三层架构

1. **数据层（bpmn-moddle）**：解析 BPMN XML 为 JavaScript 对象（moddleElement），序列化回 XML
2. **画布层（diagram-js）**：管理画布上的元素、交互、事件
3. **业务层（bpmn-js）**：BPMN 特定的规则、渲染、工具栏

**关键理解**：bpmn-js 的核心是 diagram-js，它是一个通用的图表编辑引擎。bpmn-js 只是在 diagram-js 之上加了 BPMN 业务规则。

## 2. 模块系统

bpmn-js 使用依赖注入（DI）管理模块，基于 diagram-js 的 DI 容器（类似 Angular 的注入器）。

### 模块注册

```js
import BpmnModeler from 'bpmn-js/lib/Modeler'

// 自定义模块
const customModule = {
  __init__: ['myService'],    // 声明需要初始化的服务
  myService: ['type', MyService], // 注册服务
  myRenderer: ['type', MyRenderer]
}

const modeler = new BpmnModeler({
  container: '#canvas',
  additionalModules: [customModule], // 追加模块
  moddleExtensions: {                 // 扩展数据模型
    custom: customExtension
  }
})
```

### DI 容器

bpmn-js 内部通过 `inject(fn)` 获取依赖：

```js
function MyService(eventBus, canvas, modeling) {
  // eventBus, canvas, modeling 都是 DI 容器注入的
  eventBus.on('element.click', (e) => {
    console.log('点击了', e.element)
  })
}

MyService.$inject = ['eventBus', 'canvas', 'modeling']
```

**面试话术**：bpmn-js 的模块系统类似 Angular 的依赖注入，每个模块声明自己依赖什么、提供什么，编辑器初始化时按依赖关系自动组装。要扩展功能，写一个模块注册进去就行。

## 3. 数据层（bpmn-moddle）

### XML 解析与序列化

```js
// 导入 XML
await modeler.importXML(bpmnXml)
const { warnings } = await modeler.importXML(bpmnXml)

// 导出 XML
const { xml } = await modeler.saveXML({ format: true })

// 导出 SVG
const { svg } = await modeler.saveSVG()
```

### moddleElement

bpmn-moddle 解析 XML 后，每个 BPMN 元素变成一个 moddleElement 对象：

```js
// 获取元素的业务对象
const element = elementRegistry.get('Task_1')
const bo = element.businessObject

bo.$type          // 'bpmn:Task'
bo.id             // 'Task_1'
bo.name           // '审批节点'
bo.$parent        // 父元素（通常是 process）
bo.extensionElements // 扩展属性
```

### 扩展数据模型（moddleExtensions）

定义自定义命名空间，让 bpmn-js 能识别和保存自定义属性：

```js
const customExtension = {
  name: 'custom',
  uri: 'http://example.com/custom',
  prefix: 'custom',
  xml: { tagAlias: 'lowerCase' },
  types: [
    {
      name: 'ApprovalProperties',
      superType: ['Element'],
      properties: [
        { name: 'assignee', isAttr: true, type: 'String' },
        { name: 'approverType', isAttr: true, type: 'String' },
        { name: 'formKey', isAttr: true, type: 'String' }
      ]
    }
  ],
  associations: [],
  emumerations: []
}

// 使用
const modeler = new BpmnModeler({
  moddleExtensions: { custom: customExtension }
})
```

这样导出的 XML 会在节点上带 `custom:assignee="user1"` 属性，下次导入时能正确解析回来。

## 4. 自定义 Renderer

覆盖默认的节点绘制逻辑，改变节点外观。

### 原理

bpmn-js 的 Renderer 继承自 diagram-js 的 BaseRenderer，在 `drawShape` 和 `drawConnection` 方法中决定节点怎么画。

```js
import BaseRenderer from 'diagram-js/lib/draw/BaseRenderer'
import { append as svgAppend, create as svgCreate } from 'tiny-svg'

class CustomRenderer extends BaseRenderer {
  constructor(eventBus, bpmnRenderer) {
    super(eventBus, 1500) // 优先级高于默认 Renderer（1200）
  }

  canRender(element) {
    // 只处理自定义类型的节点
    return is(element, 'bpmn:UserTask')
  }

  drawShape(parentGfx, element) {
    const shape = svgCreate('rect')
    svgAttr(shape, {
      width: element.width,
      height: element.height,
      fill: '#e8f5e9',
      stroke: '#4caf50',
      rx: 8
    })
    svgAppend(parentGfx, shape)

    // 添加文字
    const text = svgCreate('text')
    text.textContent = element.businessObject.name || ''
    svgAppend(parentGfx, text)

    return shape
  }
}

CustomRenderer.$inject = ['eventBus', 'bpmnRenderer']
```

### CPM 项目实践

在 CPM 项目中，不同类型的审批节点需要不同的视觉样式：
- 人工审批节点：绿色圆角矩形
- 自动审批节点：蓝色矩形
- 条件分支节点：橙色菱形

通过 `canRender` 判断节点类型，`drawShape` 中根据类型绘制不同样式。

## 5. 自定义 Palette

左侧工具栏，控制可以拖拽到画布上的节点类型。

### 原理

Palette 是一个提供器（Provider）模式，每个 Provider 返回一组工具项。

```js
class CustomPaletteProvider {
  constructor(bpmnFactory, create, elementFactory, handTool, palette) {
    this.bpmnFactory = bpmnFactory
    this.create = create
    this.elementFactory = elementFactory
    this.handTool = handTool

    palette.registerProvider(this) // 注册到 palette
  }

  getPaletteEntries() {
    return {
      'create.user-task': {
        group: 'activity',
        title: '创建审批节点',
        className: 'bpmn-icon-user-task',
        action: {
          click: (event) => {
            const shape = this.elementFactory.createShape({
              type: 'bpmn:UserTask'
            })
            this.create.start(event, shape)
          }
        }
      },
      'create.exclusive-gateway': {
        group: 'gateway',
        title: '创建条件分支',
        className: 'bpmn-icon-gateway-xor',
        action: {
          click: (event) => {
            const shape = this.elementFactory.createShape({
              type: 'bpmn:ExclusiveGateway'
            })
            this.create.start(event, shape)
          }
        }
      }
    }
  }
}

CustomPaletteProvider.$inject = [
  'bpmnFactory', 'create', 'elementFactory', 'handTool', 'palette'
]
```

### CPM 项目实践

CPM 的 Palette 不需要所有 BPMN 节点，只暴露业务需要的几种：开始事件、结束事件、审批节点、条件分支、连线。其他标准 BPMN 节点全部隐藏。

## 6. 属性面板（Property Panel）

最复杂的定制部分。属性面板负责编辑节点的业务属性（审批人、表单绑定、条件表达式等）。

### 架构

```
properties-panel
├── PropertiesPanel      # 面板容器
├── PropertyGroups       # 属性分组（基本、审批人、表单...）
│   ├── Group
│   │   ├── Entry       # 单个属性条目（输入框、下拉、选择器...）
│   │   └── Entry
│   └── Group
└── PropertiesActivator # 决定哪些组对当前选中元素显示
```

### 自定义属性组

```js
// PropertiesActivator：决定显示哪些属性组
class CustomPropertiesActivator {
  constructor() {}

  getGroups(element) {
    // 返回 null 表示使用默认组
    // 返回数组表示使用自定义组
    if (is(element, 'bpmn:UserTask')) {
      return [
        {
          id: 'approval',
          label: '审批配置',
          entries: [
            {
              id: 'approverType',
              label: '审批人类型',
              modelProperty: 'approverType',
              get: (element) => ({ approverType: getAttr(element, 'approverType') }),
              set: (element, values) => setAttr(element, 'approverType', values.approverType)
            },
            {
              id: 'assignee',
              label: '指定审批人',
              modelProperty: 'assignee',
              get: (element) => ({ assignee: getAttr(element, 'assignee') }),
              set: (element, values) => setAttr(element, 'assignee', values.assignee)
            }
          ]
        }
      ]
    }
    return null // 其他节点用默认属性组
  }
}
```

### CPM 项目中的难点

1. **属性与节点的绑定**：自定义属性需要存到 bpmn XML 的扩展命名空间中，属性面板读写时要通过 moddleElement 的 `extensionElements` 操作，API 文档很少
2. **属性面板刷新机制**：选中节点变化时面板要重新渲染，但 bpmn-js 的刷新机制是基于事件的，有时候面板不更新，需要手动触发
3. **复杂控件**：审批人选择器、表单绑定选择器都是业务组件，需要在 bpmn-js 的属性面板框架里嵌入 Vue 组件

### 嵌入 Vue 组件到属性面板

```js
// 在 Entry 的 html 属性中返回一个容器
function createApproverEntry(element, translate) {
  const html = document.createElement('div')
  html.id = 'approver-entry-container'

  // 用 Vue 挂载业务组件
  const app = createApp(ApproverSelector, {
    value: getApproverValue(element),
    onChange: (val) => {
      setApproverValue(element, val)
    }
  })
  app.mount(html)

  return { html }
}
```

## 7. 事件系统

bpmn-js 的事件分两层：diagram-js 的画布事件和 bpmn-js 的业务事件。

### 画布事件（diagram-js）

```js
// 通过 eventBus 监听
modeler.get('eventBus').on('element.click', (e) => {
  console.log('点击元素', e.element)
})

modeler.get('eventBus').on('shape.added', (e) => {
  console.log('新增形状', e.element)
})

modeler.get('eventBus').on('connection.added', (e) => {
  console.log('新增连线', e.element)
})

modeler.get('eventBus').on('selection.changed', (e) => {
  console.log('选区变化', e.newSelection)
})
```

### 常用事件

| 事件名 | 触发时机 | 用途 |
|--------|---------|------|
| `element.click` | 点击元素 | 节点选中、弹出属性面板 |
| `element.dblclick` | 双击元素 | 打开节点详情 |
| `shape.added` | 新增形状 | 初始化节点属性 |
| `connection.added` | 新增连线 | 校验连线规则 |
| `commandStack.changed` | 任何操作（增删改） | 保存检测、撤销重做 |
| `selection.changed` | 选区变化 | 属性面板刷新 |
| `canvas.viewbox.changed` | 画布缩放平移 | 小地图同步 |

## 8. Command Stack（撤销/重做）

bpmn-js 内置了完整的撤销/重做机制，通过 Command Stack 管理。

```js
const commandStack = modeler.get('commandStack')

// 撤销
commandStack.undo()

// 重做
commandStack.redo()

// 是否可以撤销
commandStack.canUndo()

// 监听变化
eventBus.on('commandStack.changed', () => {
  // 任何建模操作都会触发
  saveToBackend() // 自动保存
})
```

### 自定义 Command

```js
// 注册自定义命令
class UpdateApprovalCommand {
  constructor(element, newValue) {
    this.element = element
    this.oldValue = getApprovalValue(element)
    this.newValue = newValue
  }

  execute() {
    setApprovalValue(this.element, this.newValue)
  }

  undo() {
    setApprovalValue(this.element, this.oldValue)
  }
}

// 使用
commandStack.execute('update.approval', {
  element: selectedElement,
  newValue: 'user1'
})
```

## 9. 规则引擎（Rules）

控制什么操作是合法的：哪些节点可以连到哪些节点、什么能拖到哪。

```js
class CustomRules {
  constructor(bpmnRules) {
    // 继承默认规则
  }

  canConnect(source, target) {
    // 开始事件不能连到结束事件
    if (is(source, 'bpmn:StartEvent') && is(target, 'bpmn:EndEvent')) {
      return false
    }
    return true // 其他情况允许
  }

  canDrop(shape, target) {
    // 条件分支只能放在连线中间，不能自由拖拽
    if (is(shape, 'bpmn:ExclusiveGateway')) {
      return is(target, 'bpmn:Process')
    }
    return true
  }
}
```

## 10. 与 Vue/React 集成

### Vue 集成

```vue
<template>
  <div ref="container" class="bpmn-container" />
</template>

<script setup>
import { ref, onMounted, onUnmounted } from 'vue'
import BpmnModeler from 'bpmn-js/lib/Modeler'

const container = ref(null)
let modeler = null

onMounted(async () => {
  modeler = new BpmnModeler({
    container: container.value,
    additionalModules: [customModule],
    moddleExtensions: { custom: customExtension }
  })

  // 加载已有流程
  if (props.bpmnXml) {
    await modeler.importXML(props.bpmnXml)
  }

  // 监听变化自动保存
  modeler.on('commandStack.changed', async () => {
    const { xml } = await modeler.saveXML({ format: true })
    emit('change', xml)
  })
})

onUnmounted(() => {
  modeler?.destroy()
})

// 暴露方法给父组件
defineExpose({
  getXML: () => modeler?.saveXML({ format: true }),
  setXML: (xml) => modeler?.importXML(xml),
  undo: () => modeler?.get('commandStack').undo(),
  redo: () => modeler?.get('commandStack').redo()
})
</script>
```

### 注意事项

1. **生命周期管理**：组件销毁时调用 `modeler.destroy()`，否则内存泄漏
2. **容器尺寸**：bpmn-js 需要容器有确定的宽高，建议用 CSS 固定或 `ResizeObserver` 监听
3. **异步操作**：`importXML` 和 `saveXML` 都是异步的，需要 `await`
4. **Vue 响应式**：不要把 modeler 放进 `reactive()`，它内部有循环引用会导致响应式系统异常

## 回答要点

### 属性面板不更新的常见原因

1. 选中节点后面板没刷新：检查 `selection.changed` 事件是否正确监听
2. 修改属性后面板不更新：moddleElement 的属性修改后需要触发 `elements.changed` 事件
3. 自定义属性读不到：检查 moddleExtensions 是否正确配置，扩展命名空间是否匹配

### 流程图保存的完整流程

```
用户操作 → commandStack 执行命令 → model 数据更新
→ 触发 commandStack.changed 事件
→ 调用 saveXML() → bpmn-moddle 序列化 moddleElement 为 XML
→ 提交到后端
```

### 审批流场景的属性存储推荐

**推荐方案：流程结构（XML）+ 业务配置（JSON）分开存**

- XML 存流程结构（节点、连线、网关）
- JSON 存业务配置（审批人、表单绑定、条件表达式），key 是节点 id
- 保存时同时提交，后端用节点 id 关联
- 好处：不侵入 BPMN 标准，后端处理灵活，支持复杂的业务配置
