# bpmn-js 架构与定制 - 常见问题

## Q1：bpmn-js 的整体架构是怎样的？三层分别负责什么？

```
bpmn-js
├── bpmn-moddle     → 数据层：XML 解析/序列化
├── diagram-js      → 画布层：拖拽、缩放、选区、事件
└── bpmn-js 业务层  → BPMN 规则、渲染、工具栏
```

- **bpmn-moddle**：把 BPMN XML 解析成 JavaScript 对象（moddleElement），支持扩展命名空间
- **diagram-js**：通用图表编辑引擎，管理画布上的元素、交互、事件、撤销/重做
- **bpmn-js**：在 diagram-js 之上加了 BPMN 特定的规则（什么能连什么）、Renderer（怎么画节点）、Palette（左侧工具栏）

关键理解：diagram-js 是通用的，bpmn-js 只是它的一个业务层实现。如果要做非 BPMN 的图表编辑器，可以直接用 diagram-js。

## Q2：怎么自定义节点外观？

通过 Renderer。继承 `BaseRenderer`，重写 `drawShape` 方法：

1. `canRender(element)`：返回 true 表示这个 Renderer 处理该元素
2. `drawShape(parentGfx, element)`：用 SVG 绘制自定义外观
3. 构造函数传优先级数字，高于默认 Renderer（1200）就能覆盖

```js
class CustomRenderer extends BaseRenderer {
  canRender(element) {
    return is(element, 'bpmn:UserTask')
  }
  drawShape(parentGfx, element) {
    // 用 SVG 绘制自定义形状
  }
}
CustomRenderer.$inject = ['eventBus', 'bpmnRenderer']
```

## Q3：自定义属性怎么存到 BPMN XML 中？

两种方案：

**方案一：扩展 meta-model（存入 XML）**
- 通过 `moddleExtensions` 定义自定义命名空间
- 属性以 XML 属性形式存在于节点上（如 `custom:assignee="user1"`）
- 导入导出自动保留，但侵入 BPMN 标准

**方案二：独立 JSON（推荐）**
- 流程结构存 XML，业务配置存 JSON（key 是节点 id）
- 不侵入标准，后端处理灵活
- 保存时同时提交，后端用节点 id 关联

审批流场景推荐方案二。

## Q4：属性面板怎么扩展？

属性面板使用 Provider 模式：

1. 定义 `PropertiesActivator`，根据选中元素类型返回对应的属性组
2. 每个属性组包含多个 Entry（输入框、下拉、选择器）
3. Entry 有 `get` 和 `set` 方法，负责读写 moddleElement 上的属性

复杂场景（如审批人选择器）需要在 Entry 的容器中挂载 Vue/React 组件。

## Q5：属性面板选中节点后不刷新怎么办？

常见原因和解决：

1. **没监听 selection.changed 事件**：面板刷新依赖选区变化事件
2. **修改属性后没触发 elements.changed**：moddleElement 属性改了但面板不知道
3. **Vue 响应式问题**：把 modeler 放进 `reactive()` 导致内部循环引用异常

```js
// 正确做法：修改属性后手动触发刷新
function setCustomAttr(element, key, value) {
  const modeling = modeler.get('modeling')
  modeling.updateProperties(element, { [`custom:${key}`]: value })
  // modeling.updateProperties 内部会触发 elements.changed，面板自动刷新
}
```

## Q6：bpmn-js 有哪些常用事件？

| 事件 | 用途 |
|------|------|
| `element.click` | 点击节点，打开属性面板 |
| `selection.changed` | 选区变化，刷新属性面板 |
| `shape.added` / `connection.added` | 新增节点/连线，初始化属性 |
| `commandStack.changed` | 任何操作，触发自动保存 |
| `elements.changed` | 元素属性变化，刷新面板 |
| `canvas.viewbox.changed` | 画布缩放/平移，小地图同步 |

## Q7：bpmn-js 和 Vue 集成需要注意什么？

1. **销毁**：组件 `onUnmounted` 时调用 `modeler.destroy()`，否则内存泄漏
2. **不要用 reactive**：modeler 内部有循环引用，放进 `reactive()` 会出问题。用 `ref()` 或直接挂到变量上
3. **容器尺寸**：bpmn-js 需要容器有确定宽高，用 CSS 固定或 `ResizeObserver`
4. **异步操作**：`importXML` / `saveXML` 都是异步的，需要 `await`
5. **暴露方法**：通过 `defineExpose` 暴露 getXML、setXML、undo、redo 等方法给父组件

## Q8：流程图导入导出的完整流程是什么？

**导入**：
```
XML 字符串 → bpmn-moddle 解析 → moddleElement 树
→ diagram-js 在画布上创建对应元素
→ Renderer 绘制外观
```

**导出**：
```
用户操作 → commandStack 记录操作
→ saveXML() → bpmn-moddle 序列化 moddleElement → XML 字符串
→ 提交后端
```

## Q9：规则引擎怎么控制连接规则？

通过自定义 Rules 模块，重写 `canConnect`、`canDrop` 等方法：

```js
canConnect(source, target) {
  // 开始事件只能连一个出线
  if (is(source, 'bpmn:StartEvent') && source.outgoing.length >= 1) {
    return false
  }
  // 条件分支必须有两条以上出线
  if (is(source, 'bpmn:ExclusiveGateway') && source.outgoing.length >= 2) {
    return false
  }
  return true
}
```

## Q10：CPM 项目中属性面板遇到的最大难点是什么？

属性面板的扩展文档很少，很多 API 要翻源码才能搞清楚：

1. **extensionElements 操作**：自定义属性要存到 `<extensionElements>` 里，但 bpmn-js 没有封装好读写 API，需要自己通过 moddleElement 的 `get('extensionElements').values` 操作
2. **属性面板刷新不及时**：选中节点变化后面板有时候不更新，需要手动在 `selection.changed` 回调里触发 `elements.changed`
3. **嵌入业务组件**：审批人选择器是 Vue 组件，需要在 bpmn-js 的属性面板 DOM 容器里挂载，生命周期管理要处理好

解决方案：封装了一套属性读写的工具函数，统一处理 extensionElements 的增删改查，屏蔽 bpmn-js 底层 API 的复杂度。
