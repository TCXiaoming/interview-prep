# 合成层与 GPU 加速

## 核心概念

浏览器渲染分三个阶段：

```
Layout（重排）→ Paint（重绘）→ Composite（合成）
```

**合成层（Composite Layer）**：浏览器将某些元素提升为独立的合成层，由 GPU 直接处理，完全跳过 Layout 和 Paint。

### transform 和 opacity 为什么性能好

`transform` 和 `opacity` 的变化只触发 Composite 阶段，跳过了 Layout 和 Paint：

```
left/top 变化：Layout → Paint → Composite  （三步都走）
transform 变化：                 Composite  （只走最后一步）
```

GPU 处理合成层速度极快，且不占用主线程，所以动画流畅不卡顿。

### 触发合成层提升的条件

- `transform` 或 `opacity` 动画（通过 `will-change` 或动画触发）
- `will-change: transform`
- `position: fixed`
- `<video>`、`<canvas>`、`<iframe>`

## 常见追问

- `will-change` 是干什么的？
- 合成层越多越好吗？
- CSS 动画和 JS 动画哪个性能更好？

## 回答要点

**will-change**：提前告知浏览器某个属性会变化，让浏览器提前创建合成层做优化。但不要滥用，每个合成层都占用 GPU 内存。

**合成层不是越多越好**：创建合成层有内存开销，过多合成层反而导致内存占用过高，得不偿失。

**CSS 动画 vs JS 动画**：
- CSS `transform/opacity` 动画：走合成层，GPU 处理，性能最好
- JS 改 `transform`（requestAnimationFrame）：同样走合成层，性能接近
- JS 改 `left/top`：触发重排，性能最差

```css
/* 好：走合成层 */
.box { transition: transform 0.3s; }
.box:hover { transform: translateX(100px); }

/* 差：触发重排 */
.box { transition: left 0.3s; }
.box:hover { left: 100px; }
```
