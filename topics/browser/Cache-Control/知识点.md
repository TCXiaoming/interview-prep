# Cache-Control

## 核心概念

`Cache-Control` 是 HTTP/1.1 的缓存控制头，优先级高于 `Expires`。

## 常用指令对比

| 指令 | 含义 |
|------|------|
| `max-age=N` | 缓存有效期 N 秒，期间直接用本地缓存（强缓存） |
| `no-cache` | 每次必须去服务端验证（走协商缓存），本地有缓存但不能直接用 |
| `no-store` | 完全不缓存，每次都从服务端拿新的，本地不存任何副本 |
| `must-revalidate` | 缓存过期后必须去服务端验证，不能用过期缓存 |
| `public` | 可以被代理服务器缓存 |
| `private` | 只能被浏览器缓存，不能被代理缓存（默认） |

## 容易混淆的三个

**no-cache vs no-store**：
- `no-cache`：本地会存缓存，但每次用之前必须问服务端"还有效吗"，服务端说有效返回 304，说无效返回新内容
- `no-store`：本地完全不存，每次都是全新请求，没有任何缓存行为

**no-cache vs must-revalidate**：
- `no-cache`：不管缓存有没有过期，每次都要验证
- `must-revalidate`：只有缓存过期了才去验证，没过期直接用

## 常见追问

- `Cache-Control` 和 `Expires` 哪个优先级高？
- 强缓存命中时，HTTP 状态码是多少？
- 如何给静态资源设置"永久缓存"？

## 回答要点

**Cache-Control 优先级高于 Expires**：两个都有时以 `Cache-Control: max-age` 为准。

**强缓存命中的状态码**：200（from cache），不发请求到服务端。协商缓存命中是 304。

**静态资源永久缓存方案**：
```
Cache-Control: max-age=31536000, immutable
```
配合文件名加 hash（如 `main.a1b2c3.js`），内容变了 hash 变，URL 变，缓存自动失效。这是现代前端构建的标准做法。

```
# HTML 文件（入口）不缓存，每次验证
Cache-Control: no-cache

# JS/CSS/图片（带 hash）永久缓存
Cache-Control: max-age=31536000, immutable
```
