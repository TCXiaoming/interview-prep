# 跨域与同源策略

## 核心概念

**同源**：协议 + 域名 + 端口三者完全相同。任意一个不同即为跨域。

**同源策略**：浏览器安全机制，阻止页面读取跨域资源（防止 CSRF、数据窃取）。注意：跨域请求能发出去，是浏览器拦截了响应。

## 常见解决方案

### 1. CORS（服务端设置响应头）
```
Access-Control-Allow-Origin: https://example.com
Access-Control-Allow-Methods: GET, POST, PUT
Access-Control-Allow-Headers: Content-Type
```

### 2. 开发环境代理（Vite/Webpack）
```js
// vite.config.js
server: {
  proxy: {
    '/api': { target: 'http://backend:8080', changeOrigin: true }
  }
}
```

### 3. JSONP（仅 GET，已过时）
利用 `<script src>` 不受同源限制，服务端返回函数调用形式的 JS。

## 带 Cookie 的跨域（credentials 三件套）

普通 CORS 不携带 Cookie，需要三个条件同时满足：

**服务端**：
```
Access-Control-Allow-Origin: https://example.com  // 不能是 *
Access-Control-Allow-Credentials: true
```

**前端**：
```js
// fetch
fetch(url, { credentials: 'include' })

// axios
axios.defaults.withCredentials = true
```

**三个条件缺一不可**：
1. `Access-Control-Allow-Credentials: true`
2. `Access-Control-Allow-Origin` 必须是具体域名，不能是 `*`
3. 前端请求设置 `credentials: 'include'`

## 常见追问

- 简单请求和预检请求（preflight）的区别？
- CORS 的 OPTIONS 预检请求是什么时候触发的？
- 子域之间怎么共享 Cookie？

## 回答要点

**预检请求（OPTIONS）**：非简单请求（PUT/DELETE、自定义 Header、Content-Type 为 application/json 等）会先发一个 OPTIONS 请求询问服务器是否允许，服务器返回允许后才发真正的请求。

**子域共享 Cookie**：设置 Cookie 的 `domain` 为顶级域名（如 `.example.com`），子域之间可以共享，但这和跨域 CORS 是两回事。

**`Access-Control-Allow-Origin` 不支持通配子域**：必须精确匹配，`*.example.com` 写法无效，需要服务端动态读取请求的 Origin 并判断是否在白名单内再返回。
