# 浏览器渲染流程

## 核心概念

从 HTML 到页面显示的完整流程：

```
HTML → DOM树
CSS  → CSSOM树  →  渲染树(Render Tree) → Layout(布局) → Paint(绘制) → Composite(合成)
```

### 渲染树的构建规则

渲染树 ≠ DOM树，以下节点**不会**出现在渲染树中：

1. **不可见的结构节点**：`<head>`、`<script>`、`<meta>`、`<link>` 等
2. **display: none 的节点**：从渲染树中完全移除（子节点也不会出现）
3. **注意**：`visibility: hidden` 和 `opacity: 0` 的节点**仍在渲染树中**，只是不可见

### JS 加载对渲染的影响

- 普通 `<script>`：阻塞 HTML 解析，遇到就停下来执行
- `async`：异步加载，加载完立即执行，不保证顺序
- `defer`：异步加载，等 DOMContentLoaded 前按顺序执行

## 常见追问

- DOMContentLoaded 和 load 事件的区别？
- CSS 会阻塞渲染吗？
- 什么是合成层（Composite Layer）？

## 回答要点

**DOMContentLoaded vs load**：
- `DOMContentLoaded`：DOM 解析完成即触发，不等图片/CSS等资源
- `load`：所有资源（图片、CSS、JS）全部加载完才触发

**CSS 阻塞**：CSS 不阻塞 DOM 解析，但阻塞渲染（需要 CSSOM 才能构建渲染树）。CSS 也会阻塞其后的 JS 执行（因为 JS 可能操作样式）。

**合成层优化**：`transform`、`opacity` 动画会触发 GPU 合成，跳过 Layout 和 Paint，性能最好。这是 CSS 动画优于 JS 动画的核心原因。
