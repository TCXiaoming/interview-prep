# 首屏加载优化

## 核心概念

### 首屏加载的关键路径

```
DNS 解析 → TCP 连接 → TLS 握手 → HTML 下载 → HTML 解析
    → CSS 下载 → CSS 解析 → DOM + CSSOM → Render Tree → Layout → Paint → Composite
    → JS 下载 → JS 执行 → 数据请求 → 页面渲染
```

首屏加载时间 = TTFB + 关键资源下载时间 + 渲染时间

### SSR vs CSR vs SSG vs ISR

| 方案 | 首屏速度 | SEO | 服务端压力 | 适用场景 |
|---|---|---|---|---|
| CSR | 慢（白屏） | 差 | 低 | 后台管理系统 |
| SSR | 快 | 好 | 高 | C 端、需要 SEO |
| SSG | 最快 | 好 | 无 | 博客、文档站、营销页 |
| ISR | 快 | 好 | 低 | 内容变化不频繁的 C 端 |

### 流式渲染（Streaming SSR）

React 18 的 `renderToPipeableStream` 支持流式渲染：
- HTML 分块传输，浏览器可以边接收边渲染
- 配合 `Suspense`，非关键内容可以延迟加载
- TTFB 不被慢数据阻塞

```jsx
// 服务端
app.get('/', (req, res) => {
  const { pipe } = renderToPipeableStream(
    <Suspense fallback={<Skeleton />}>
      <SlowComponent />  {/* 这个组件可能需要等数据 */}
    </Suspense>,
    {
      onShellReady() {
        res.setHeader('Content-Type', 'text/html');
        pipe(res);  // Shell 先发出去，不等 SlowComponent
      }
    }
  );
});
```

### 资源加载策略

```html
<!-- 关键 CSS：内联在 head 中 -->
<style>/* 首屏关键 CSS */</style>

<!-- 非关键 CSS：异步加载 -->
<link rel="preload" href="non-critical.css" as="style" onload="this.rel='stylesheet'">

<!-- 关键 JS：defer（不阻塞解析，DOM 解析完后执行） -->
<script src="app.js" defer></script>

<!-- 非关键 JS：async（下载完就执行，不保证顺序） -->
<script src="analytics.js" async></script>

<!-- 预连接关键域名 -->
<link rel="preconnect" href="https://api.example.com">
<link rel="dns-prefetch" href="https://cdn.example.com">
```

## 常见追问

### Q: 你的项目首屏优化具体做了什么？

**参考回答（贷后自助服务平台）：**

我们用了 Next.js 14 App Router，首屏优化做了这几件事：

1. **SSR + 流式渲染** — 用 React Suspense 把页面分成多个区块，Shell 先渲染出去，慢数据的区块显示 Skeleton。LCP 从 3.2s 降到 1.1s。

2. **服务端数据预取** — 还款计划数据在 SSR 阶段就拿到了，客户端不需要再发一次请求，消除了数据请求瀑布。

3. **图片优化** — 用 Next/Image 组件，自动转 WebP、根据设备尺寸裁剪、lazy loading。凭证图片的传输体积减少了 60%。

4. **字体优化** — 用 `font-display: swap` 避免字体加载阻塞渲染，用 `next/font` 自动子集化。

5. **非首屏延迟加载** — 信用报告这种用户不一定会看的模块，用 `dynamic()` 动态导入，首屏不加载。

### Q: SSR 首屏快但服务端压力大，怎么平衡？

**回答要点：**
1. **边缘渲染** — 把 SSR 逻辑放到 CDN 边缘节点（Vercel Edge Runtime、Cloudflare Workers），减少源站压力
2. **缓存策略** — SSR 结果用 `stale-while-revalidate` 缓存，用户拿到的是缓存的 HTML，后台异步更新
3. **ISR（增量静态再生）** — 对不常变的页面用 ISR，首次 SSR 后缓存为静态页
4. **Streaming SSR** — 流式渲染减少服务端占用时间
5. **降级方案** — 服务端超时自动降级为 CSR，保证可用性

## 回答要点总结

1. 首屏优化是一个系统工程，不是某一个点
2. 有前后对比数据最有说服力
3. 理解不同渲染方案的 trade-off
4. 结合自己的项目实际经验来说
