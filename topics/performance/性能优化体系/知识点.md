# 前端性能优化体系

## 核心概念

### 性能指标（Core Web Vitals）

| 指标 | 含义 | 优秀标准 | 测量方式 |
|---|---|---|---|
| **LCP**（Largest Contentful Paint） | 最大内容渲染时间 | < 2.5s | PerformanceObserver |
| **FID**（First Input Delay）→ **INP**（Interaction to Next Paint） | 首次输入延迟/交互延迟 | < 100ms | PerformanceObserver |
| **CLS**（Cumulative Layout Shift） | 累计布局偏移 | < 0.1 | PerformanceObserver |
| **FCP**（First Contentful Paint） | 首次内容渲染 | < 1.8s | PerformanceObserver |
| **TTFB**（Time to First Byte） | 首字节时间 | < 800ms | Navigation Timing |

### 性能优化分层

```
网络层 → 资源层 → 渲染层 → 运行时层
  ↓        ↓        ↓        ↓
DNS/CDN  压缩/拆包  关键渲染路径  内存/计算
```

### 一、网络层优化

1. **DNS 预解析** — `<link rel="dns-prefetch" href="//api.example.com">`
2. **CDN 加速** — 静态资源上 CDN，利用边缘节点缓存
3. **HTTP/2 或 HTTP/3** — 多路复用、头部压缩、服务器推送
4. **减少请求数** — 合理使用雪图/Sprite、合并小文件（但 HTTP/2 下不是重点）
5. **TLS 1.3** — 减少握手往返

### 二、资源层优化

1. **代码分割（Code Splitting）**
   - 路由级分割：`React.lazy()` + `Suspense`
   - 组件级分割：动态 `import()`
   - 第三方库分割：Webpack `splitChunks`

2. **Tree Shaking** — 消除未使用的代码，需要 ESM 模块规范

3. **压缩**
   - Gzip / Brotli（Brotli 压缩率更高，约比 Gzip 小 15-20%）
   - JS 压缩：Terser / esbuild / SWC
   - CSS 压缩：cssnano

4. **图片优化**
   - 格式选择：WebP > JPEG（照片）、SVG（图标）、AVIF（最新但兼容性差）
   - 响应式图片：`<picture>` + `srcset`
   - 懒加载：`loading="lazy"` 或 IntersectionObserver
   - 自动裁剪：Next.js `<Image>` 组件

5. **字体优化**
   - `font-display: swap` — 避免字体加载阻塞渲染
   - 子集化：只打包用到的字符

### 三、渲染层优化

1. **关键渲染路径优化**
   - CSS 放 `<head>`，JS 放 `</body>` 前或加 `defer`/`async`
   - 内联关键 CSS（首屏样式）
   - 减少 DOM 节点数量（虚拟列表、分页）

2. **避免强制同步布局**
   ```js
   // 错误：读写交替触发强制同步布局
   element.style.height = '100px';
   console.log(element.offsetHeight); // 触发 reflow
   element.style.width = '200px';
   ```

3. **使用 transform 代替 top/left 做动画** — 走合成层，不触发 reflow

4. **长任务拆分** — 超过 50ms 的任务会阻塞主线程，用 `requestIdleCallback` 或 `scheduler` 拆分

### 四、运行时层优化

1. **虚拟列表** — 大量数据只渲染可视区域
2. **防抖/节流** — scroll、resize、input 等高频事件
3. **Web Worker** — CPU 密集型计算移出主线程
4. **内存管理** — 避免闭包泄漏、及时清理事件监听器和定时器
5. **React 特有**
   - `React.memo` / `useMemo` / `useCallback` 避免不必要的重渲染
   - `useTransition` / `useDeferredValue` 标记低优先级更新
   - 列表必须加 `key`

## 常见追问

### Q: 你是怎么做首屏优化的？

**回答要点（结合贷后自助服务平台）：**
1. SSR + 流式渲染（React Suspense），LCP 从 3.2s 降到 1.1s
2. 首屏关键 CSS 内联，非关键 CSS 异步加载
3. 图片用 Next/Image 自动裁剪 + WebP，传输体积减少 60%
4. 接口数据在服务端预取，减少客户端请求瀑布
5. 非首屏组件用动态 `import()` 延迟加载

### Q: Webpack 打包太大，怎么优化？

**回答要点：**
1. **分析包内容** — `webpack-bundle-analyzer` 找大模块
2. **代码分割** — `splitChunks` 拆分 vendor、按路由懒加载
3. **Tree Shaking** — 确保用 ESM、`sideEffects: false`
4. **替换大依赖** — moment.js → dayjs、lodash → lodash-es（按需引入）
5. **压缩** — Terser 压缩 JS、开启 Gzip/Brotli
6. **CDN 外链** — 大型稳定依赖（React、Vue）用 CDN 引入，不打进 bundle

### Q: 怎么监控线上性能？

**回答要点：**
1. **RUM（Real User Monitoring）** — 采集真实用户数据，不是只看 Lighthouse
2. **Performance Observer API** — 采集 LCP、FID、CLS 等指标
3. **上报到后端** — `navigator.sendBeacon()` 可靠上报
4. **Sentry / 自建平台** — 做聚合分析、异常告警
5. **分维度分析** — 按设备类型、网络条件、地理位置分析性能差异

## 回答要点总结

1. 有体系地说，不要东一榔头西一棒子
2. 每个优化手段要能说清楚原理 — "为什么这样做有效"
3. 结合实际项目数据 — 优化前后的指标对比
4. 了解最新的性能指标（INP 替代 FID）和优化手段
