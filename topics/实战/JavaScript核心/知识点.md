# JavaScript 核心（实战向）

## 执行上下文与 this

### 执行上下文三要素

1. **变量环境** — var 声明、函数声明（变量提升）
2. **词法环境** — let/const 声明（块级作用域、暂时性死区）
3. **外部引用** — 作用域链，决定变量查找路径

### this 绑定规则（优先级从高到低）

```
new 绑定 > 显式绑定（call/apply/bind）> 隐式绑定（obj.fn()）> 默认绑定（独立调用）
```

**易错点：**
```js
const obj = {
  name: 'obj',
  fn: function() { return this.name; }
};
const fn = obj.fn;
fn(); // undefined — 赋值给变量后变成独立调用，this 指向 window/undefined

// 箭头函数没有自己的 this，继承定义时外层作用域的 this
const obj2 = {
  name: 'obj2',
  fn: () => this.name // this 不是 obj2，是外层的 this
};
```

### bind/apply/call 区别

| 方法 | 执行时机 | 参数 | 返回值 |
|---|---|---|---|
| call | 立即执行 | 逐个传参 | 函数返回值 |
| apply | 立即执行 | 数组传参 | 函数返回值 |
| bind | 不立即执行 | 逐个传参 | 绑定 this 后的新函数 |

**手写 bind：**
```js
Function.prototype.myBind = function(ctx, ...args) {
  const fn = this;
  return function(...innerArgs) {
    // 如果是 new 调用，this 应该是新创建的对象而不是 ctx
    if (new.target) {
      return new fn(...args, ...innerArgs);
    }
    return fn.apply(ctx, [...args, ...innerArgs]);
  };
};
```

## 闭包

**定义：** 函数能够记住并访问其定义时的词法作用域，即使函数在其他地方执行。

**经典场景：**
```js
// 循环中的闭包问题
for (var i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 100); // 全部输出 5
}
// 解决：用 let（块级作用域）或 IIFE 创建闭包
for (let i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 100); // 0,1,2,3,4
}
```

**内存泄漏风险：**
- 闭包持有外部变量的引用，如果闭包长期不释放，外部变量也无法被 GC
- 常见于：事件监听器未移除、定时器未清除、DOM 引用未置空

## 原型链

```
instance.__proto__ === Constructor.prototype
Constructor.prototype.__proto__ === Object.prototype
Object.prototype.__proto__ === null
```

**prototype vs __proto__：**
- `prototype` 是函数特有的属性，指向原型对象
- `__proto__` 是所有对象都有的属性（内部属性 `[[Prototype]]`），指向构造函数的 prototype

**ES5 继承 vs ES6 继承：**
```js
// ES5：组合继承
function Parent(name) { this.name = name; }
Parent.prototype.sayName = function() { return this.name; };
function Child(name, age) {
  Parent.call(this, name); // 借用构造函数
  this.age = age;
}
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;

// ES6：class 继承（语法糖，底层还是原型链）
class Parent {
  constructor(name) { this.name = name; }
  sayName() { return this.name; }
}
class Child extends Parent {
  constructor(name, age) {
    super(name);
    this.age = age;
  }
}
```

## 事件循环

```
┌─────────────────────────┐
│       Call Stack         │
└───────────┬─────────────┘
            ↓ 同步代码执行完
┌─────────────────────────┐
│   Microtask Queue       │  Promise.then, MutationObserver, queueMicrotask
│   （清空所有微任务）       │
└───────────┬─────────────┘
            ↓
┌─────────────────────────┐
│   Macrotask Queue       │  setTimeout, setInterval, I/O, UI rendering
│   （取一个宏任务）        │
└───────────┬─────────────┘
            ↓ 回到顶部，循环
```

**关键规则：**
- 一个宏任务执行完后，清空所有微任务，再执行下一个宏任务
- 微任务优先级高于宏任务
- `process.nextTick`（Node.js）优先级高于 Promise.then

## Promise

**手写 Promise 核心：**
```js
class MyPromise {
  constructor(executor) {
    this.state = 'pending';
    this.value = undefined;
    this.onFulfilledCallbacks = [];
    this.onRejectedCallbacks = [];

    const resolve = (value) => {
      if (this.state !== 'pending') return;
      this.state = 'fulfilled';
      this.value = value;
      // 异步执行回调（模拟微任务）
      queueMicrotask(() => {
        this.onFulfilledCallbacks.forEach(fn => fn(value));
      });
    };

    const reject = (reason) => {
      if (this.state !== 'pending') return;
      this.state = 'rejected';
      this.reason = reason;
      queueMicrotask(() => {
        this.onRejectedCallbacks.forEach(fn => fn(reason));
      });
    };

    try { executor(resolve, reject); }
    catch (e) { reject(e); }
  }

  then(onFulfilled, onRejected) {
    return new MyPromise((resolve, reject) => {
      const handleFulfilled = (val) => {
        try {
          const result = onFulfilled ? onFulfilled(val) : val;
          // 如果返回的是 Promise，需要等待
          result instanceof MyPromise ? result.then(resolve, reject) : resolve(result);
        } catch (e) { reject(e); }
      };
      // ... 类似处理 rejected
      if (this.state === 'fulfilled') queueMicrotask(() => handleFulfilled(this.value));
      else if (this.state === 'pending') this.onFulfilledCallbacks.push(handleFulfilled);
    });
  }
}
```

### Promise.all / race / allSettled / any

| 方法 | 行为 | 失败处理 |
|---|---|---|
| `all` | 全部成功才成功 | 一个失败立即失败 |
| `race` | 第一个完成的结果 | 第一个失败则失败 |
| `allSettled` | 全部完成后返回每个结果 | 不会 reject |
| `any` | 第一个成功的结果 | 全部失败才 reject（AggregateError） |

## 深拷贝

```js
function deepClone(obj, map = new WeakMap()) {
  if (obj === null || typeof obj !== 'object') return obj;
  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj);
  // 处理循环引用
  if (map.has(obj)) return map.get(obj);

  const clone = Array.isArray(obj) ? [] : {};
  map.set(obj, clone);

  // 处理 Symbol 属性
  Reflect.ownKeys(obj).forEach(key => {
    clone[key] = deepClone(obj[key], map);
  });
  return clone;
}
```

## 防抖与节流

```js
// 防抖：最后一次触发后等 delay 执行
function debounce(fn, delay) {
  let timer = null;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 节流：每隔 delay 执行一次
function throttle(fn, delay) {
  let last = 0;
  return function(...args) {
    const now = Date.now();
    if (now - last >= delay) {
      last = now;
      fn.apply(this, args);
    }
  };
}
```

## instanceof 手写

```js
function myInstanceOf(obj, Constructor) {
  let proto = Object.getPrototypeOf(obj);
  const target = Constructor.prototype;
  while (proto !== null) {
    if (proto === target) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}
```

## 事件委托

**原理：** 利用事件冒泡，将事件绑定在父元素上，通过 `event.target` 判断实际触发的子元素。

**优点：**
1. 减少事件处理器数量，降低内存占用
2. 动态添加的子元素自动拥有事件处理能力
3. 不需要在子元素销毁时移除事件监听

**限制：** 不冒泡的事件不能委托（`focus`、`blur`、`scroll` — 可用捕获阶段替代）

## 并发控制

```js
async function concurrentControl(tasks, maxConcurrency) {
  const results = [];
  let running = 0;
  let index = 0;

  return new Promise((resolve) => {
    const runNext = () => {
      while (running < maxConcurrency && index < tasks.length) {
        const i = index++;
        running++;
        tasks[i]().then(result => {
          results[i] = result;
        }).finally(() => {
          running--;
          if (running === 0 && index >= tasks.length) {
            resolve(results);
          }
          runNext();
        });
      }
    };
    runNext();
  });
}
```

## 常见追问

### Q: 为什么 setTimeout 不精确？

**回答要点：**
setTimeout 的回调进入宏任务队列，但执行时机取决于：
1. 前面是否有未执行完的同步代码和微任务
2. 浏览器的渲染时机（每帧约 16.7ms）
3. HTML5 规范规定嵌套超过 5 层的 setTimeout 最小延迟 4ms

所以 `setTimeout(fn, 0)` 不是立即执行，而是"尽快执行"。

### Q: 如何判断一个对象是否为空？

```js
// 只检查自身可枚举属性
Object.keys(obj).length === 0;
// 包含不可枚举属性
Object.getOwnPropertyNames(obj).length === 0;
// 包含 Symbol 属性
Reflect.ownKeys(obj).length === 0;
```

### Q: 数组去重有哪些方法？

```js
// 1. Set
[...new Set(arr)];
// 2. filter + indexOf
arr.filter((item, index) => arr.indexOf(item) === index);
// 3. reduce
arr.reduce((acc, cur) => acc.includes(cur) ? acc : [...acc, cur], []);
// 4. Map — 适用于对象数组（按某个 key 去重）
const seen = new Map();
arr.filter(item => !seen.has(item.id) && seen.set(item.id, true));
```
