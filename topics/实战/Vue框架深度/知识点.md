# Vue 框架深度（实战向）

## Vue 2 响应式原理

### 核心三角色

```
Observer（数据观测） → 每个响应式属性对应一个 Dep（依赖收集器）
Dep（依赖收集器）    → 存储所有依赖该属性的 Watcher
Watcher（观察者）    → 关联一个更新函数，属性变化时触发执行
```

**流程：**
1. `new Vue()` 时遍历 data，用 `Object.defineProperty` 将每个属性转为 getter/setter
2. 渲染时触发 getter，Dep 收集当前 Watcher（渲染 Watcher）
3. 数据变化触发 setter，Dep 通知所有 Watcher 执行更新

**Vue 2 的局限：**
- 无法检测对象属性的添加/删除（需要 `Vue.set` / `Vue.delete`）
- 无法直接监听数组下标修改（重写了 `push/pop/splice/unshift/shift/reverse/sort`）
- 初始化时需要递归遍历所有属性，深层对象性能差

## Vue 3 响应式原理（Proxy）

```js
function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      track(target, key); // 依赖收集
      return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
      const result = Reflect.set(target, key, value, receiver);
      trigger(target, key); // 触发更新
      return result;
    },
    deleteProperty(target, key) {
      const result = Reflect.deleteProperty(target, key);
      trigger(target, key);
      return result;
    }
  });
}
```

**Proxy 的优势：**
- 能监听属性的增删
- 能监听数组下标修改和 length 变化
- 不需要初始化时递归遍历（惰性代理，访问时才代理嵌套对象）
- 支持 Map、Set 等集合类型

### ref vs reactive

| 维度 | ref | reactive |
|---|---|---|
| 数据类型 | 基本类型 + 对象 | 只能是对象 |
| 访问方式 | 需要 `.value`（模板中自动解包） | 直接访问 |
| 替换整个值 | 可以直接赋新值 | 不能整体替换（会丢失响应式） |
| 底层实现 | 内部对对象类型用 reactive 包装 | Proxy |

```ts
// ref 的本质
function ref(value) {
  return {
    get value() { track(...); return value; },
    set value(newVal) { value = newVal; trigger(...); }
  };
}
```

### Vue 3 为什么同时提供 ref 和 reactive？

**回答要点：**
- `ref` 可以包装任何值（包括基本类型），可以整体替换，适合函数间传递
- `reactive` 只能包装对象，解构后会丢失响应式
- `ref` 的 `.value` 是显式的响应式标记，让代码更清晰（知道哪些是响应式的）
- 实际项目中：推荐 `ref` 作为主要 API，`reactive` 用于局部对象状态

## Vue 3 虚拟 DOM Diff 优化

### 传统 Diff 的问题

传统 diff 算法是 O(n³) — 两棵树的所有节点两两比较。Vue/React 通过"同层比较 + key 匹配"优化到 O(n)。

### Vue 3 的优化点

1. **静态提升（Static Hoisting）**
   - 编译时识别出不变的节点，提升到 render 函数外
   - 每次渲染不需要重新创建这些 VNode

2. **补丁标志（Patch Flags）**
   - 编译时标记每个动态节点的变化类型（文本、class、style、props...）
   - diff 时只比较标记了的部分，跳过静态内容
   ```js
   // 编译产物示例
   createVNode('div', { class: cls, id: id }, children, PatchFlags.CLASS | PatchFlags.PROPS)
   ```

3. **Block 树**
   - 将模板中的动态节点收集到一个扁平数组中
   - diff 时直接遍历这个数组，不需要递归整棵树

4. **最长递增子序列**
   - 列表 diff 时，找到最长递增子序列，减少 DOM 移动次数
   - 场景：列表排序、插入、删除时，尽量复用已有 DOM 节点

## Vue 3.5+ 新特性

### alien-signals（Vue 3.6 提案）

**是什么：** Vue 响应式系统的底层重构，用信号（Signal）机制替代当前的实现。

**核心概念：**
- **Signal（信号）** — 类似 ref，表示一个可变的数据源
- **Computed（计算信号）** — 自动追踪依赖，惰性求值
- **Effect（副作用）** — 依赖变化时自动执行
- **传播模型** — Push-Pull 混合模型，数据变化时 push 通知，但实际计算延后到 pull 时

**用栈替代递归：**
- 当前响应式系统用递归追踪依赖，深层嵌套可能栈溢出
- alien-signals 用显式栈结构管理依赖关系，避免栈溢出

**位运算优化：**
- 用位掩码标记节点状态（dirty、recursed、pending）
- 状态判断用位运算，比布尔标志更快

### useTemplateRef（Vue 3.5）

```vue
<script setup>
import { useTemplateRef } from 'vue';
const inputRef = useTemplateRef('my-input');
// 等价于 ref + template ref 字符串绑定
onMounted(() => inputRef.value.focus());
</script>

<template>
  <input ref="my-input" />
</template>
```

### Props 响应式更新（Vue 3.5）

Vue 3.5 中 props 的响应式更新不再需要 shallowRef 包装，框架内部做了优化，props 的更新更高效。

## $nextTick 原理

```js
// Vue 2
const callbacks = [];
let pending = false;
function flushCallbacks() {
  pending = false;
  const copies = callbacks.slice(0);
  callbacks.length = 0;
  copies.forEach(cb => cb());
}

function nextTick(cb) {
  callbacks.push(() => {
    if (cb) cb.call(ctx);
  });
  if (!pending) {
    pending = true;
    // 优先使用微任务：Promise > MutationObserver > setImmediate > setTimeout
    timerFunc();
  }
}
```

**为什么需要 nextTick？**
Vue 的 DOM 更新是异步的（批量更新），修改数据后 DOM 还没更新，`nextTick` 确保在 DOM 更新后执行回调。

## Vue 生命周期

```
beforeCreate → created → beforeMount → mounted → beforeUpdate → updated → beforeUnmount → unmounted
     ↓            ↓          ↓           ↓           ↓              ↓
   初始化       可访问       模板编译     DOM 挂载    数据变化        DOM 更新
   data/methods  data/methods 完成        完成        准备更新       更新完成
```

**父组件和子组件的执行顺序：**
- 挂载：父 beforeCreate → ... → 父 beforeMount → 子 beforeCreate → ... → 子 mounted → 父 mounted
- 更新：父 beforeUpdate → 子 beforeUpdate → 子 updated → 父 updated
- 卸载：父 beforeUnmount → 子 beforeUnmount → 子 unmounted → 父 unmounted

## computed 缓存机制

```js
// 简化版实现
function computed(getter) {
  let value;
  let dirty = true; // 缓存标志

  const runner = effect(getter, {
    lazy: true,
    scheduler() {
      dirty = true; // 依赖变化时标记为脏
      trigger(obj, 'value');
    }
  });

  return {
    get value() {
      if (dirty) {
        value = runner(); // 只在脏时重新计算
        dirty = false;
      }
      return value; // 否则返回缓存值
    }
  };
}
```

**缓存了什么：** 缓存了上一次的计算结果。只有依赖变化时才重新计算。
**不支持异步：** computed 的价值在于同步地派生状态，异步结果无法被追踪。

## watch vs computed

| 维度 | computed | watch |
|---|---|---|
| 用途 | 派生新值 | 执行副作用 |
| 返回值 | 必须有返回值 | 不需要返回值 |
| 缓存 | 有缓存 | 无缓存 |
| 同步 | 必须同步 | 可以异步 |
| 使用场景 | 模板中显示计算结果 | 发请求、修改 DOM、日志 |

## 常见追问

### Q: Vue 2 为什么 data 必须是函数？

**回答要点：**
组件可能被多次实例化（如列表中的组件）。如果 data 是对象，所有实例共享同一个引用，修改一个实例的 data 会影响其他实例。返回函数保证每个实例有独立的数据副本。

### Q: 为什么 Vue 3 Composition API 比 Options API 好？

**回答要点：**
- **逻辑复用** — Composition API 用 composable 函数复用逻辑，Options API 用 mixins（命名冲突、来源不清）
- **类型推导** — Composition API 天然支持 TypeScript，Options API 的 `this` 类型推导困难
- **代码组织** — Composition API 按逻辑功能组织代码，Options API 按选项类型分散代码
- **Tree-shaking** — Composition API 支持按需引入，Options API 不行

但 Options API 更简单直观，适合简单组件。Vue 3 两种 API 都支持，不强制迁移。
