# 工程化实战

## Webpack

### 构建流程

```
初始化参数 → 创建 Compiler → 加载插件 → 开始编译 → 确定入口
→ 从 entry 出发 → 调用 Loader 转换 → 解析 AST → 收集依赖
→ 递归处理依赖 → 完成模块编译 → 生成 chunks → 输出文件
```

### Loader vs Plugin

| 维度 | Loader  | Plugin         |
| -- | ------- | -------------- |
| 作用 | 文件内容转换  | 干预构建流程         |
| 时机 | 模块加载阶段  | 整个编译生命周期       |
| 本质 | 一个函数    | 一个含 apply 方法的类 |
| 方向 | 文件 → JS | 钩子切入           |

**常用 Loader：**

- `babel-loader` / `esbuild-loader` — JS 转译
- `css-loader` → `style-loader` / `MiniCssExtractPlugin.loader` — CSS 处理
- `ts-loader` / `esbuild-loader` — TypeScript
- `file-loader` / `url-loader` / `asset module` — 文件资源

**常用 Plugin：**

- `HtmlWebpackPlugin` — 生成 HTML
- `MiniCssExtractPlugin` — CSS 提取为独立文件
- `TerserWebpackPlugin` — 压缩 JS
- `DefinePlugin` — 定义全局常量
- `CopyWebpackPlugin` — 复制静态文件

### Webpack Loader Demo

**Loader 本质：** 一个函数，接收源码字符串，返回转换后的源码字符串。

```js
// loaders/add-banner-loader.js
// 给每个 JS 文件头部注入版本注释
module.exports = function(source) {
  const options = this.getOptions() || {};
  const banner = `/* ${options.name || 'app'} v${options.version || '1.0.0'} */`;
  return `${banner}\n${source}`;
};

// loaders/markdown-loader.js
// 将 .md 文件转为 HTML 字符串（导出为 JS 模块）
const { marked } = require('marked');

module.exports = function(source) {
  const html = marked.parse(source);
  // 导出一个 JS 模块，让后续 Loader/Plugin 可以处理
  return `export default ${JSON.stringify(html)};`;
};

// loaders/console-loader.js
// 在每个 console.log 前注入文件名和行号（调试用）
module.exports = function(source) {
  const resourcePath = this.resourcePath;
  // 用正则替换 console.log 为带位置信息的版本
  return source.replace(
    /console\.log\(/g,
    `console.log("[${resourcePath}]", `
  );
};
```

**Webpack 配置使用 Loader：**

```js
// webpack.config.js
const path = require('path');

module.exports = {
  module: {
    rules: [
      {
        test: /\.js$/,

      },
      {
        test: /\.md$/,
        use: [
          'html-loader',                          // 将 HTML 转为 JS 模块
          path.resolve(__dirname, 'loaders/markdown-loader.js')
        ]
      }
    ]
  }
};
```

### Webpack Plugin Demo

**Plugin 本质：** 一个类，实现 `apply(compiler)` 方法，通过 Tapable 钩子介入构建流程。

```js
// plugins/file-list-plugin.js
// 在构建产物中生成一个 fileList.json，列出所有输出文件
class FileListPlugin {
  constructor(options = {}) {
    this.filename = options.filename || 'fileList.json';
  }

  apply(compiler) {
    // emit 钩子：产物输出到目录前一刻（此时 assets 已确定）
    compiler.hooks.emit.tap('FileListPlugin', (compilation) => {
      const files = Object.keys(compilation.assets).map(name => ({
        name,
        size: compilation.assets[name].size(),
      }));

      const content = JSON.stringify({ files, count: files.length }, null, 2);

      // 向 assets 中添加新文件
      compilation.assets[this.filename] = {
        source: () => content,
        size: () => content.length,
      };
    });
  }
}

// plugins/env-check-plugin.js
// 构建时检查环境变量是否完整，缺失则报错
class EnvCheckPlugin {
  constructor(requiredEnvs = []) {
    this.requiredEnvs = requiredEnvs;
  }

  apply(compiler) {
    // environment 钩子：编译器环境准备好后
    compiler.hooks.environment.tap('EnvCheckPlugin', () => {
      const missing = this.requiredEnvs.filter(key => !process.env[key]);
      if (missing.length > 0) {
        throw new Error(`Missing required env vars: ${missing.join(', ')}`);
      }
    });
  }
}

// plugins/console-time-plugin.js
// 打印构建耗时
class ConsoleTimePlugin {
  apply(compiler) {
    compiler.hooks.compile.tap('ConsoleTimePlugin', () => {
      this.startTime = Date.now();
    });

    compiler.hooks.done.tap('ConsoleTimePlugin', (stats) => {
      const duration = Date.now() - this.startTime;
      console.log(`\n  Build completed in ${duration}ms`);
      console.log(`  Chunks: ${stats.compilation.chunks.size}`);
    });
  }
}

module.exports = { FileListPlugin, EnvCheckPlugin, ConsoleTimePlugin };
```

**Webpack 配置使用 Plugin：**

```js

```

### Webpack 常用钩子速查

| 钩子            | 类型 | 触发时机                      |
| ------------- | -- | ------------------------- |
| `entryOption` | 同步 | entry 配置处理后               |
| `compile`     | 同步 | 编译开始前                     |
| `compilation` | 同步 | 新的 compilation 创建后        |
| `emit`        | 异步 | 产物输出到目录前（最后修改 assets 的机会） |
| `done`        | 同步 | 编译完成                      |
| `failed`      | 同步 | 编译失败                      |

### 热更新（HMR）原理

```
文件变化 → Webpack 增量编译 → 生成新的 chunk
→ 通过 WebSocket 通知客户端 → 客户端请求更新的模块
→ 执行 module.hot.accept 回调 → 局部更新 DOM
→ 没有 accept → 整页刷新（fallback）
```

## Vite

### 开发模式构建流程

```
启动 dev server
  → 读取 vite.config.js，合并默认配置
  → 创建 Koa/Connect 中间件服务器
  → 依赖预构建（esbuild）
  → 监听文件变化（chokidar）
  → 等待浏览器请求

浏览器请求 index.html
  → Vite 返回 HTML（注入 HMR client + import map）

浏览器解析 HTML，发现 <script type="module" src="/src/main.ts">
  → 请求 main.ts
  → Vite 拦截请求 → 调用插件链（resolveId → load → transform）
  → 如果是 .ts → esbuild 编译为 JS（极快）
  → 如果是 .vue → @vitejs/plugin-vue 拆分为 template + script + style
  → 如果是 .css → 提取为 JS 模块（插入 <style> 标签）
  → 返回转换后的 ESM 模块

浏览器发现 import 语句 → 继续请求子模块 → 按需编译 → 递归执行
```

**关键点：**

- 开发时不做打包，浏览器通过原生 ESM 按需请求每个模块
- 每个模块请求都会经过 Vite 的插件 transform 链
- 不需要构建依赖图，不需要全量编译，启动秒开

### 依赖预构建（optimizeDeps）

**为什么需要？**

1. **CommonJS → ESM** — 浏览器不支持 CJS，需要转换
2. **合并小文件** — 减少请求数（lodash-es 有 600+ 个文件，合并为 1 个）

**流程：**

```
扫描源码中的 import 语句
  → 找到 node_modules 中的依赖
  → 用 esbuild 将 CJS/UMD 转为 ESM（Go 编写，比 JS 快 10-100 倍）
  → 将多文件依赖合并为单文件
  → 输出到 node_modules/.vite/deps/
  → 写入 _metadata.json 缓存清单
```

**触发时机：**

- 首次启动
- `package.json` 或 `vite.config.js` 变化
- 手动 `vite optimize --force`
- `optimizeDeps.include` / `exclude` 配置变化

### 生产模式构建流程

```
vite build
  → 读取 vite.config.js
  → 用 Rollup 做全量打包（不是 esbuild）
  → Rollup 解析所有模块 → 构建依赖图
  → Tree Shaking（Rollup 基于 ESM 静态分析，比 Webpack 更彻底）
  → Code Splitting（自动按动态 import 拆分 chunk）
  → 调用插件的 renderChunk / generateBundle 钩子
  → Terser/esbuild 压缩
  → 输出到 dist/ 目录
      ├── index.html
      ├── assets/
      │   ├── index-[hash].js
      │   ├── vendor-[hash].js
      │   └── index-[hash].css
```

**为什么生产用 Rollup 不用 esbuild？**

- esbuild 速度快但功能不够：不支持 CSS 处理、不支持 HTML 生成、代码分割能力弱
- Rollup 生态成熟，插件丰富，Tree Shaking 最优
- 生产构建只需要执行一次，速度不是最重要的，产物质量和兼容性更重要

### HMR 原理

```
启动时 → Vite 创建 WebSocket 服务器 → 浏览器 HMR Client 连接

文件变化（chokidar 检测到）
  → 确定受影响的模块边界（精确到模块级，不是 chunk 级）
  → 执行插件的 handleHotUpdate 钩子
  → 通过 WebSocket 发送 update 事件
      { type: 'update', updates: [{ type: 'js-update', path: '/src/App.vue', acceptedPath: '/src/App.vue', timestamp: 1700000000 }] }

浏览器收到消息
  → fetch 更新的模块（带时间戳参数避免缓存）
  → 执行 accept 回调（局部更新）
  → 没有 accept → 向上冒泡找父模块
  → 都找不到 → 触发 full-reload（整页刷新）
```

**Vite HMR vs Webpack HMR：**

- Webpack：变化模块所在的整个 chunk 重新构建，chunk 越大越慢
- Vite：只让变化的模块及其导入者失效，精确到单个模块，几乎瞬间完成

### 插件系统

Vite 插件扩展了 Rollup 插件接口，并添加了 Vite 特有的钩子。

**执行顺序：**

```
config（修改配置）
  → configResolved（配置已解析）
  → configureServer（配置 dev server 中间件）
  → buildStart（构建开始）
  → resolveId（解析模块路径）
  → load（加载模块内容）
  → transform（转换模块内容）
  → buildEnd（构建结束）
  → closeBundle（关闭）
```

**常用钩子分类：**

| 阶段 | 钩子                               | 用途         |
| -- | -------------------------------- | ---------- |
| 配置 | `config` / `configResolved`      | 修改/读取最终配置  |
| 开发 | `configureServer`                | 添加 dev 中间件 |
| 开发 | `transformIndexHtml`             | 修改 HTML 内容 |
| 通用 | `resolveId`                      | 自定义模块解析    |
| 通用 | `load`                           | 自定义模块加载    |
| 通用 | `transform`                      | 转换模块内容     |
| 构建 | `renderChunk` / `generateBundle` | 修改打包产物     |

### Vite Plugin Demo 1：自动添加文件头注释

```JavaScript
// plugins/banner.js
// 给每个 JS/CSS 文件头部注入版本信息

export function bannerPlugin(options = {}) {
  const { name = 'app', version = '1.0.0' } = options;
  const banner = `/* ${name} v${version} - ${new Date().toISOString().split('T')[0]} */`;

  return {
    name: 'vite-plugin-banner',

    // transform 钩子：每个模块加载后都会经过这里
    transform(code, id) {
      // 只处理 src 目录下的 JS/CSS 文件
      if (!id.includes('/src/') || !/\.(js|ts|jsx|tsx|css)$/.test(id)) return;

      return {
        code: `${banner}\n${code}`,
        map: null, // 不修改 source map
      };
    },
  };
}

// vite.config.js 使用
import { bannerPlugin } from './plugins/banner.js';

export default {
  plugins: [
    bannerPlugin({ name: 'my-app', version: '2.0.0' }),
  ],
};
```

```js
// plugins/size-report.js
// 构建完成后输出每个文件的大小报告

export function sizeReportPlugin() {
  return {
    name: 'vite-plugin-size-report',

    // generateBundle 钩子：打包产物生成后、写入磁盘前
    generateBundle(options, bundle) {
      const report = [];

      for (const [fileName, chunk] of Object.entries(bundle)) {
        let size;
        if (chunk.type === 'chunk') {
          size = Buffer.byteLength(chunk.code, 'utf-8');
        } else if (chunk.type === 'asset') {
          size = Buffer.byteLength(
            typeof chunk.source === 'string' ? chunk.source : '',
            'utf-8'
          );
        }
        report.push({ fileName, size: `${(size / 1024).toFixed(2)} KB` });
      }

      console.log('\n  Build Size Report:');
      console.table(report);
    },
  };
}
```

### Vite Plugin Demo 3：自定义文件解析 + 虚拟模块

```js
// plugins/virtual-module.js
// 创建一个虚拟模块，自动生成运行时配置

export function virtualConfigPlugin() {
  const virtualModuleId = 'virtual:config';
  const resolvedVirtualModuleId = '\0' + virtualModuleId; // Vite 约定用 \0 前缀

  return {
    name: 'vite-plugin-virtual-config',

    // resolveId 钩子：拦截模块路径解析
    resolveId(id) {
      if (id === virtualModuleId) {
        return resolvedVirtualModuleId; // 返回解析后的路径
      }
    },

    // load 钩子：加载模块内容
    load(id) {
      if (id === resolvedVirtualModuleId) {
        // 动态生成模块内容
        return `
          export const config = {
            version: "${process.env.npm_package_version || '1.0.0'}",
            buildTime: "${new Date().toISOString()}",
            env: "${process.env.NODE_ENV || 'development'}",
          };
          export default config;
        `;
      }
    },
  };
}
```

```js
// plugins/api-mock.js
// 开发环境下 mock API 接口

export function apiMockPlugin(mockData = {}) {
  return {
    name: 'vite-plugin-api-mock',

    // configureServer 钩子：配置开发服务器中间件
    configureServer(server) {
      server.middlewares.use((req, res, next) => {
        // 匹配 /api 开头的请求

        next(); // 不匹配则放行
      });
    },
  };
}
```

## Babel 工作原理

```
源码 → 解析（Parser） → AST → 转换（Transform）→ AST → 生成（Generator） → 新代码
```

1. **Parse** — 词法分析 + 语法分析，生成 AST
2. **Transform** — 遍历 AST，通过 Plugin 修改节点
3. **Generate** — 将 AST 转回代码字符串

**Preset vs Plugin：**

- Plugin 是单个转换规则（如箭头函数转普通函数）
- Preset 是一组 Plugin 的集合（如 `@babel/preset-env` 包含所有 ES6+ 转 ES5 的 Plugin）

## 幽灵依赖

**问题：** 在 `node_modules` 中，A 依赖 B，你没装 B 但 `require('B')` 能找到（因为 B 在 `node_modules/A/node_modules/B` 或扁平化后在根 `node_modules/B`）。B 升级或移除后代码就报错。

**解决：**

1. 所有依赖显式声明在 `package.json` 中
2. 使用 pnpm（严格模式，每个包只能访问自己声明的依赖）
3. 使用 `dependency-check` 工具检测未声明的依赖

2. **构建层** — Vite（新项目）/ Webpack（老项目），统一构建配置
3. **组件层** — 部门级组件库（Vue 3 + Element Plus），5+ 项目复用
4. **监控层** — Sentry 错误监控 + OpenTelemetry 链路追踪
5. **CI/CD** — GitLab CI / Jenkins 自动化构建部署

### Q: package.json 中 dependencies vs devDependencies

**回答要点：**

- `dependencies` — 运行时依赖，打包进产物（React、Vue、axios）
- `devDependencies` — 开发时依赖，不打包进产物（ESLint、Webpack、TypeScript）
- `npm install --production` 只装 dependencies
- 但对于前端项目（最终产物是静态文件），这个区分的实际意义不大 — 构建时所有依赖都在 node\_modules 中
