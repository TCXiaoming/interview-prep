# TypeScript（实战向）

## 基础类型系统

### 类型注解

```ts
// 变量
let name: string = 'hello';
let count: number = 42;
let isActive: boolean = true;

// 函数
function add(a: number, b: number): number { return a + b; }

// 数组
let nums: number[] = [1, 2, 3];
let names: Array<string> = ['a', 'b'];

// 元组
let point: [number, number] = [1, 2];

// 对象
let user: { name: string; age: number } = { name: 'test', age: 25 };
```

### 接口（Interface）

```ts
// 定义对象形状
interface User {
  id: number;
  name: string;
  email?: string;  // 可选属性
  readonly createdAt: Date;  // 只读
}

// 继承
interface Admin extends User {
  role: 'admin';
  permissions: string[];
}

// 函数签名
interface Fetcher {
  (url: string): Promise<Response>;
}

// 索引签名
interface Cache {
  [key: string]: any;
}
```

### 类型别名（Type Alias）

```ts
// 基本类型别名
type ID = string | number;

// 联合类型
type Status = 'pending' | 'approved' | 'rejected';

// 交叉类型
type Admin = User & { role: 'admin'; permissions: string[] };

// 工具类型
type PartialUser = Partial<User>;
type RequiredUser = Required<User>;
type PickedUser = Pick<User, 'id' | 'name'>;
type OmittedUser = Omit<User, 'email'>;
```

### Interface vs Type

| 维度 | Interface | Type |
|---|---|---|
| 扩展 | `extends` | `&` 交叉类型 |
| 合并声明 | 可以（同名自动合并） | 不可以 |
| 适用场景 | 对象形状定义 | 联合类型、交叉类型、工具类型 |
| 映射类型 | 不支持 | 支持 |

**选择建议：** 定义对象用 Interface，其他场景用 Type。实际项目中混用很常见。

## 高级类型

### 泛型

```ts
// 泛型函数
function identity<T>(value: T): T { return value; }
identity<string>('hello');
identity(42); // 类型推断

// 泛型约束
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

// 泛型接口
interface ApiResponse<T> {
  code: number;
  data: T;
  message: string;
}

// 泛型工具类型
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyPick<T, K extends keyof T> = { [P in K]: T[P] };
```

### 条件类型

```ts
// 基本条件类型
type IsString<T> = T extends string ? true : false;

// 分发条件类型
type ToArray<T> = T extends any ? T[] : never;
type StrOrNumArray = ToArray<string | number>; // string[] | number[]

// infer 推断
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type UnwrapPromise<T> = T extends Promise<infer U> ? U : T;
type ElementOf<T> = T extends Array<infer E> ? E : never;
```

### 映射类型

```ts
// 基本映射
type Readonly<T> = { readonly [K in keyof T]: T[K] };
type Mutable<T> = { -readonly [K in keyof T]: T[K] };

// 修改修饰符
type Required<T> = { [K in keyof T]-?: T[K] };  // 去掉可选
type Partial<T>  = { [K in keyof T]?: T[K] };   // 加可选

// 重映射（as）
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
// { name: string } → { getName: () => string }
```

### 模板字面量类型

```ts
type EventName = `on${Capitalize<'click' | 'focus' | 'blur'>}`;
// 'onClick' | 'onFocus' | 'onBlur'

type CSSProperty = `${string}-${string}`;
// 匹配任何 'xxx-xxx' 格式的字符串

type Route = `/${string}`;
// 匹配以 / 开头的路径
```

## TypeScript 在项目中的实际价值

### 类型安全的 API 层

```ts
// 用 OpenAPI 生成类型定义
interface Endpoints {
  '/api/users': {
    GET: { response: User[]; query: { page: number } };
    POST: { response: User; body: CreateUserDto };
  };
  '/api/users/:id': {
    GET: { response: User; params: { id: string } };
    PUT: { response: User; params: { id: string }; body: UpdateUserDto };
  };
}

// 类型安全的 fetch 封装
async function api<T extends keyof Endpoints, M extends keyof Endpoints[T]>(
  url: T,
  method: M,
  options?: Endpoints[T][M]
): Promise<Endpoints[T][M] extends { response: infer R } ? R : never> {
  // ...
}
```

### 类型守卫

```ts
// 自定义类型守卫
function isError(value: unknown): value is Error {
  return value instanceof Error;
}

function isUser(obj: any): obj is User {
  return typeof obj?.name === 'string' && typeof obj?.id === 'number';
}

// 使用
if (isError(result)) {
  console.log(result.message); // result 类型收窄为 Error
}

// discriminated union
type Shape =
  | { type: 'circle'; radius: number }
  | { type: 'rect'; width: number; height: number };

function area(shape: Shape): number {
  switch (shape.type) {
    case 'circle': return Math.PI * shape.radius ** 2;
    case 'rect': return shape.width * shape.height;
  }
}
```

## 常见追问

### Q: TypeScript 的优势是什么？

**回答要点：**
1. **编译时错误检测** — 运行前就发现类型错误，不等到上线才出问题
2. **IDE 支持** — 自动补全、重构、跳转定义、类型提示
3. **代码即文档** — 类型定义就是最好的 API 文档
4. **重构安全** — 改了类型，所有引用的地方都会报错，不会漏改
5. **团队协作** — 新人看类型定义就能理解数据结构，不用读代码

### Q: TypeScript 有什么缺点？

**回答要点：**
1. **学习成本** — 高级类型（泛型、条件类型、infer）有门槛
2. **编译时间** — 大项目类型检查慢
3. **类型体操** — 过度设计类型会导致代码可读性变差
4. **any 陷阱** — `any` 会绕过所有类型检查，团队可能滥用
5. **和运行时无关** — TypeScript 类型在编译后被擦除，运行时不保证类型安全

### Q: 你项目中 TypeScript 规范是怎样的？

**回答要点：**
1. `strict: true` 打开所有严格检查
2. `noImplicitAny` — 不允许隐式 any
3. `strictNullChecks` — 必须处理 null/undefined
4. 接口命名不加 `I` 前缀（统一用 PascalCase）
5. 组件 Props 用 interface 定义
6. 工具函数用泛型保持灵活性
