# useEffect 与 useLayoutEffect

## 核心概念

两者都用于处理副作用，区别在于**执行时机**：

| <br /> | useEffect              | useLayoutEffect         |
| ------ | ---------------------- | ----------------------- |
| 执行时机   | 浏览器绘制**之后**异步执行        | DOM 更新后、浏览器绘制**之前**同步执行 |
| 是否阻塞绘制 | 否                      | 是                       |
| 类比     | componentDidMount（异步版） | componentDidMount（同步版）  |

**选择原则**：读了 DOM 还要改 → 用 `useLayoutEffect`，否则用 `useEffect`。

## 常见追问

### Q: useLayoutEffect 会阻塞绘制，什么场景下值得用？

**回答要点：**

需要"读取 DOM 布局 → 立即修改样式/位置"的场景。如果不用 useLayoutEffect 而用 useEffect，流程会变成：

```
DOM 更新 → 浏览器绘制（错误位置）→ useEffect 执行 → setState → 重新渲染 → 绘制（正确位置）
```

用户会看到元素"闪"一下。useLayoutEffect 把修改在绘制前做完：

```
DOM 更新 → useLayoutEffect 执行 → setState → 重新渲染（同一帧内）→ 浏览器绘制（正确位置）
```

典型场景：

- **tooltip 定位**：根据触发元素的 getBoundingClientRect() 计算弹窗位置，防止弹窗出现在错误位置后又跳回来
- **动画初始位置**：从 API 拿到数据后计算起始坐标
- **滚动位置恢复**：列表切换后恢复滚动位置

```jsx
function Tooltip({ targetRef }) {
  const [pos, setPos] = useState({ top: 0, left: 0 });
  useLayoutEffect(() => {
    const rect = targetRef.current.getBoundingClientRect();
    setPos({ top: rect.bottom + 8, left: rect.left });
    // 绘制前完成位置计算，用户看不到弹窗在 (0,0) 闪烁
  }, [targetRef]);
  return <div style={{ position: 'absolute', ...pos }}>...</div>;
}
```

### Q: useEffect 里读 DOM 准确吗？

**回答要点：**

**读是准确的**。useEffect 执行时浏览器已经绘制完毕，DOM 已经是最终状态。`getBoundingClientRect()`、`offsetHeight` 等读取操作拿到的值和 useLayoutEffect 里是一样的。

问题出在**读了之后又修改**：

```jsx
// ❌ 会闪烁
useEffect(() => {
  const h = ref.current.offsetHeight;
  setHeight(h * 2);       // 触发二次渲染，用户看到高度变化的过程
}, []);
```

useEffect 执行 → 用户已看到第一次渲染结果 → setState → 二次渲染 → 用户看到闪烁。这种情况下就应该用 useLayoutEffect。

### Q: SSR 场景下 useLayoutEffect 有什么问题？

**回答要点：**

`useLayoutEffect` 在服务端渲染时**不会执行**（服务端没有 DOM 和浏览器 API），而且 React 会在控制台打印 warning。

根本原因：服务端执行 useLayoutEffect 没有意义（没有 DOM 可操作），同时它依赖的 DOM API（getBoundingClientRect、offsetHeight 等）在服务端根本不存在。

**解决方案：**

1. 如果逻辑不依赖 DOM → 直接改用 `useEffect`（SSR 下也不执行，但不报 warning）
2. 如果逻辑依赖 DOM → 用 `useEffect` + 条件判断，只在客户端执行：

```jsx
// 方案 1：检测环境
const useIsomorphicLayoutEffect = typeof window !== 'undefined'
  ? useLayoutEffect
  : useEffect;

// 方案 2：Next.js 中动态导入组件时禁用 SSR
const Tooltip = dynamic(() => import('./Tooltip'), { ssr: false });
```

Q: 多个 useLayoutEffect 的执行顺序和性能影响？

**回答要点：**

**执行顺序**：串行执行，按组件树深度优先、定义顺序依次执行。所有 useLayoutEffect 执行完毕后才交还浏览器进行绘制。

**性能影响**：如果多个 useLayoutEffect 里有大量同步计算（比如遍历大数组、复杂 DOM 测量），会累积阻塞浏览器绘制时间。用户会感知到页面**卡顿**——点击按钮后屏幕没有立即响应。

```jsx
// ❌ 多个 useLayoutEffect 串行执行大量计算
function HeavyComponent() {
  useLayoutEffect(() => {
    for (let i = 0; i < 1000000; i++) measure(); // 阻塞
  });
  useLayoutEffect(() => {
    for (let i = 0; i < 1000000; i++) compute(); // 继续阻塞
  });
  // 两个都执行完，浏览器才能绘制
}
```

**建议**：能不阻塞绘制的场景尽量用 useEffect。只有"不阻塞就会闪烁"的场景才用 useLayoutEffect。

### Q: useLayoutEffect 对应类组件的哪个生命周期？

**回答要点：**

对应 `componentDidMount`（挂载时）和 `componentDidUpdate`（更新时）的**同步版本**。实际上 React 源码在 Commit 阶段的 layout 子阶段就是这样实现的：

```
Commit 阶段：
  before mutation → mutation (DOM 更新) → layout（同步执行）
                                              ↓
                                     componentDidMount
                                     componentDidUpdate
                                     useLayoutEffect ← 同队列
```

useEffect 则是在浏览器绘制完成后，通过 Scheduler 异步调度执行，不在 Commit 阶段的调用路径中。
