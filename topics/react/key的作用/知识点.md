# key 的作用

## 核心概念

`key` 是 React diff 算法中节点的**唯一身份标识**，帮助 React 判断节点是新增、移动还是删除，而不是销毁重建。

**没有 key**：React 按位置对比，位置变了就认为是不同节点，触发不必要的销毁重建。

**有 key**：React 按 key 对比，能识别出节点只是移动了，复用已有 DOM。

## 常见追问

- 为什么不能用 index 做 key？
- 用 index 做 key 会有什么具体 bug？
- key 必须全局唯一吗？

## 回答要点

**index 做 key 的 bug**：index 随列表变化而变化，插入/删除后 key 对应关系错乱。

具体场景：列表 A(0)、B(1)、C(2)，每项有 input，用户在 B 的 input 输入"hello"。头部插入 X，变成 X(0)、A(1)、B(2)、C(3)。React 认为 key=1 的节点没变（还是 A），但复用了原来 key=1 的 DOM（B 的 input），导致 A 的 input 里出现"hello"——**UI 状态跟着 DOM 走，而不是跟着数据走**。

**key 的作用范围**：只需在同级兄弟节点中唯一，不需要全局唯一。

**什么时候可以用 index**：列表只展示、不增删不排序时，用 index 没问题。
