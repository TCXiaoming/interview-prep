# 合成事件

## 核心概念

React 在原生事件基础上封装的事件系统，统一了跨浏览器的事件差异，提供一致的 API。

**事件委托**：React 不在每个 DOM 节点上绑定事件，而是统一委托到容器节点：
- React 16：委托到 `document`
- React 17+：委托到根容器节点（`ReactDOM.render` 挂载的 div）

**React 17 改动原因**：支持多个 React 版本在同一页面共存。如果都委托到 `document`，事件冒泡会互相干扰。

## 常见追问

- 合成事件和原生事件混用会有什么问题？
- 为什么 React 17 把委托从 document 改到根容器？
- 合成事件对象是复用的吗？（React 17 之前的池化机制）

## 回答要点

**混用问题**：在原生事件里调用 `stopPropagation()` 会阻止事件冒泡到根容器，导致 React 的合成事件收不到该事件。

**React 17 之前的事件池**：合成事件对象是复用的，事件回调执行完后属性会被清空。所以异步访问事件对象需要先调用 `e.persist()`。React 17 移除了这个机制。

```jsx
// React 16 需要 persist
handleClick(e) {
  e.persist()
  setTimeout(() => console.log(e.target), 0) // 否则 e.target 为 null
}

// React 17+ 不需要
handleClick(e) {
  setTimeout(() => console.log(e.target), 0) // 正常
}
```
