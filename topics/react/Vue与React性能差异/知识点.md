# Vue 与 React 性能差异

## 核心概念

两者的真实差异不在于"同步 vs 异步"，而在于**更新粒度和调度机制**。

### Vue 3 的更新机制

- 响应式系统（Proxy）精确追踪依赖，只有用到该数据的组件才会重新渲染
- diff 是单次同步完成的，但通过 `nextTick`（微任务）批量合并同一事件循环内的多次更新，避免重复渲染
- 单次 diff 量大时，一帧内算不完会阻塞主线程

### React Fiber 的更新机制

- 默认全树 diff（无精确依赖追踪），依赖 `React.memo`、`useMemo` 等手动优化
- Fiber 时间切片：将 diff 计算拆分为多个小任务，在每帧空闲时间执行，超时暂停让出主线程
- 高优先级更新（用户交互）可以打断低优先级更新（数据加载）

## 关键差异对比

| | Vue 3 | React (Fiber) |
|---|---|---|
| 依赖追踪 | 自动精确（Proxy） | 手动优化（memo） |
| diff 方式 | 单次同步 | 时间切片，可中断 |
| 批量更新 | nextTick 微任务 | 自动批处理（React 18） |
| 大数据场景 | 单次 diff 可能阻塞 | 时间切片不阻塞主线程 |

## 常见追问

- Vue 3 的 diff 是同步的，那为什么平时感觉不卡？
- React 时间切片在什么场景下才能体现优势？
- Vue 3 有没有类似时间切片的方案？

## 回答要点

**Vue 平时不卡的原因**：精确依赖追踪使得每次 diff 的范围很小，不需要全树对比，所以单次 diff 很快。只有在极大数据量（如万级列表）的场景下，单次 diff 才会成为瓶颈。

**React 时间切片的真正价值**：不是让 diff 更快，而是让 diff 不阻塞用户交互。即使计算量大，用户点击、输入等高优先级操作依然流畅响应。

**正确的选型说法**：React 在超大数据量、高交互复杂度的场景下调度能力更强；Vue 3 在中等规模场景下因精确依赖追踪反而性能更好，且开发成本更低。
