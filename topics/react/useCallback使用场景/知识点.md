# useCallback 使用场景

## 核心概念

`useCallback` 缓存函数引用，依赖不变时返回同一个函数对象。但**缓存本身有开销**，只有在特定场景下才真正有价值。

## 有意义的两个场景

### 场景一：配合 React.memo

子组件用 `React.memo` 包裹时，父组件传入的函数引用变化会导致 memo 失效：

```jsx
// 父组件
const handleClick = useCallback(() => {
  doSomething(id)
}, [id]) // id 不变则函数引用不变

// 子组件用 memo 包裹，props 不变就不重渲染
const Child = React.memo(({ onClick }) => (
  <button onClick={onClick}>Click</button>
))
```

不用 `useCallback`：父组件每次渲染都创建新函数 → `React.memo` 比较发现引用变了 → 子组件重渲染（memo 失效）。

### 场景二：函数放入 useEffect 依赖数组

```jsx
const fetchData = useCallback(async () => {
  const res = await api.get(url)
  setData(res)
}, [url]) // url 不变则函数引用不变

useEffect(() => {
  fetchData()
}, [fetchData]) // fetchData 引用稳定，effect 不会无限触发
```

不用 `useCallback`：每次渲染都创建新的 `fetchData` → `useEffect` 依赖变化 → effect 无限触发。

## 没有意义的场景

```jsx
// 子组件没有 React.memo，useCallback 完全无意义
const handleClick = useCallback(() => {}, []) // 白白增加开销

function Child({ onClick }) { // 普通组件，父组件重渲染它就重渲染
  return <button onClick={onClick}>Click</button>
}
```

## 常见追问

### Q: useCallback 和 useMemo 的关系是什么？

**回答要点：**

`useCallback(fn, deps)` 本质上等价于 `useMemo(() => fn, deps)`。两者底层是同一个实现，只是语义不同：

```js
// 这两行等价
useCallback(fn, deps);
useMemo(() => fn, deps);
```

- **useCallback**：返回缓存的**函数本身**。适合"我要缓存这个函数引用"的场景
- **useMemo**：返回缓存的**计算结果**。适合"我要缓存这个计算值"的场景

```jsx
const handleClick = useCallback(() => doSomething(id), [id]);
// 等价于：
const handleClick = useMemo(() => () => doSomething(id), [id]);

const sortedList = useMemo(() => list.sort(), [list]);
// useCallback 做不了这个
```

`useCallback` 只是 `useMemo` 的一种特例——缓存函数。选择依据是意图表达：用 `useCallback` 表示"我要稳定函数引用"，用 `useMemo` 表示"我要避免重复计算"。

### Q: 什么时候不应该用 useCallback？

**回答要点：**

useCallback 本身有开销（比普通函数定义多出依赖比较 + 缓存存取），所以以下场景用是**负优化**：

**1. 子组件没有 React.memo**
```jsx
// ❌ 子组件没有 memo，父组件重渲染子组件必然重渲染
const handleClick = useCallback(() => {}, []);
<Child onClick={handleClick} />

function Child({ onClick }) { /* 普通组件，父渲染它就渲染 */ }
```

没有 `React.memo` 时，子组件不看 props 引用是否变化——父组件渲染它就渲染。useCallback 的缓存完全没有意义，还多消耗内存。

**2. 函数没有放入任何 hook 的依赖数组**
```jsx
// ❌ onClick 只用于 DOM 事件，不参与任何 hook 的依赖比较
const handleClick = useCallback(() => setCount(c => c + 1), []);
<button onClick={handleClick}>+</button>
```

DOM 事件监听不需要引用稳定性，每次渲染重新创建函数是最简单的做法。

**3. 渲染开销本身很小**
```jsx
// ❌ 一个简单的按钮，重渲染成本极低
const handleClick = useCallback(() => setOpen(!open), [open]);
<Button onClick={handleClick}>切换</Button>
```

useCallback 的缓存比较逻辑 + 内存占用可能比重渲染一个简单按钮的代价还大。

**原则**：先写 `function handleClick() {}`，当发现配合 `React.memo` 的子组件不必要地重渲染时，再加 `useCallback`。**不要提前优化**。

### Q: useCallback 的依赖数组怎么填？

**回答要点：**

和 `useEffect`/`useMemo` 一样——**闭包内引用到的所有外部变量都要填入**。遗漏会导致闭包陷阱，拿到过期值。

```jsx
// ❌ 依赖缺失
const handleClick = useCallback(() => {
  console.log(count); // count 是当前渲染的快照值，之后永远拿不到更新的 count
}, []);

// ✅ 正确
const handleClick = useCallback(() => {
  console.log(count);
}, [count]);
```

**常见的陷阱场景：**

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  // ❌ 陷阱：一直加 1（依赖缺失）
  const increment = useCallback(() => {
    setCount(count + 1); // count 永远是最初的值
  }, []);

  // ✅ 正确方式 1：传入依赖
  const increment = useCallback(() => {
    setCount(count + 1);
  }, [count]);

  // ✅ 正确方式 2：用函数式更新，完全不需要依赖
  const increment = useCallback(() => {
    setCount(c => c + 1);
  }, []); // 不引用外部变量，依赖数组为空是安全的
}
```

**核心规则**：如果函数内只用到了 setState 的函数式更新（`c => c + 1`）或 useRef 的值，可以不加依赖。其他情况下，eslint-plugin-react-hooks 的 `exhaustive-deps` 规则会提示你该填什么。

### Q: useCallback 和"过早优化"的关系是什么？怎么判断该不该用？

**回答要点：**

useCallback 是 React 社区被滥用最多的 hook，面试常考这个判断力。

| 场景 | 用不用 | 原因 |
|------|--------|------|
| `<button onClick={fn}>` | ❌ 不用 | 原生 DOM 元素，重渲染成本极低 |
| `<Child onClick={fn} />` | ❌ 不用 | 子组件没有 memo，用了白用 |
| `<MemoChild onClick={fn} />` | ✅ 用 | memo 依赖引用稳定性，不用则 memo 失效 |
| `useEffect` 里调用的函数 | ✅ 用 | 函数作为依赖，不用会导致 effect 无限循环 |

**一句话判断**：如果函数引用变化会导致某个不该重渲染的组件重渲染、或某个不该触发的 effect 触发，就用。否则不用。

### Q: 实现一个 useCallback 的简化版本？

**回答要点：**

```js
function useCallback(callback, deps) {
  const ref = useRef(null);

  // 首次渲染或依赖变化时更新
  if (!ref.current || !deps || !areDepsEqual(ref.current.deps, deps)) {
    ref.current = { callback, deps };
  }

  return ref.current.callback;
}

function areDepsEqual(prevDeps, nextDeps) {
  if (prevDeps.length !== nextDeps.length) return false;
  return prevDeps.every((dep, i) => Object.is(dep, nextDeps[i]));
}
```

核心逻辑就是：保存上一次的依赖数组和回调函数，每次渲染时用 `Object.is` 逐个比较依赖，没变就返回旧引用，变了才更新。
