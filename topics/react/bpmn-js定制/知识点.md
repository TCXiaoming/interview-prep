# bpmn-js 定制

## 核心概念

bpmn-js 的定制主要分三个层面：

1. **自定义 Renderer**：覆盖默认的节点绘制逻辑，改变节点外观
2. **自定义 Palette**：修改左侧工具栏，增删可用的流程节点类型
3. **属性面板扩展**：在右侧属性面板增加业务自定义属性

## 自定义属性存储方案

### 方案一：存入 bpmn XML（扩展 meta-model）

通过自定义命名空间扩展 bpmn 标准，属性随 XML 一起保存：

```js
// 定义扩展 meta-model
const customExtension = {
  name: 'custom',
  uri: 'http://custom',
  prefix: 'custom',
  xml: { tagAlias: 'lowerCase' },
  types: [{
    name: 'CustomTask',
    extends: ['bpmn:Task'],
    properties: [{ name: 'assignee', isAttr: true, type: 'String' }]
  }]
}
// 节点上会有 custom:assignee="xxx" 属性
```

优点：数据与流程定义绑定，导入导出完整
缺点：需要后端解析自定义命名空间，侵入 bpmn 标准

### 方案二：独立维护 JSON 数据结构

属性面板的值单独存一个对象，key 是节点 id：

```js
const nodeProperties = {
  'task_1': { assignee: 'user1', formKey: 'form_001' },
  'task_2': { assignee: 'user2', formKey: 'form_002' }
}
```

优点：不侵入 bpmn 标准，后端处理灵活，审批流场景更常用
缺点：需要额外维护节点 id 与属性的映射关系

## 常见追问

- 自定义属性怎么在属性面板和流程图之间同步？
- 流程图导出时自定义属性怎么处理？
- bpmn-js 的模块化架构是怎样的？

## 回答要点

审批流场景推荐方案二：流程结构（XML）和业务配置（JSON）分开存，后端分别解析，职责清晰。保存时同时提交 bpmn XML 和 nodeProperties JSON，后端用节点 id 关联。
