# Vite 原理与对比

## 核心概念

### Vite 的核心理念

> 利用浏览器原生 ESM 支持，开发时不需要打包，只在生产构建时用 Rollup 打包。

```
Webpack 开发模式：文件变化 → 全量重编译 → 输出 bundle → 浏览器刷新
Vite 开发模式：    文件变化 → 只编译该模块 → 浏览器请求更新的模块
```

### Vite 开发模式架构

```
浏览器请求 index.html
  → Vite 解析 HTML，发现 <script type="module" src="/src/main.ts">
  → 浏览器请求 main.ts
  → Vite 编译 main.ts（esbuild），返回 ES module
  → 浏览器发现 import { createApp } from 'vue'
  → 浏览器请求 /node_modules/.vite/vue.js?v=xxx（预构建后的依赖）
  → Vite 返回预构建后的依赖
  → 以此类推，按需编译...
```

### 依赖预构建（Optimize Deps）

**为什么需要预构建？**
1. CommonJS / UMD 依赖不能直接用 ESM 导入 → 需要转为 ESM
2. 有些依赖内部有很多小文件（如 lodash-es 有 600+ 个文件）→ 合并为一个文件，减少请求数

**预构建过程：**
- 使用 esbuild（Go 编写）做预构建，速度极快
- 结果缓存在 `node_modules/.vite/` 目录
- 只在首次启动或 `package.json` / `vite.config.js` 变化时重新构建

```js
// vite.config.js — 强制预构建某个依赖
optimizeDeps: {
  include: ['some-cjs-library']
}
```

### Vite 的 HMR

```
文件变化
  → Vite 确定受影响的模块范围（精确到模块级，不是 chunk 级）
  → 通过 WebSocket 发送更新消息
  → 客户端收到消息，fetch 新的模块内容
  → 执行模块的 accept 回调，局部更新
```

**Vite HMR vs Webpack HMR：**
- Webpack：需要重新构建整个 chunk（包含变化模块的那个 chunk），chunk 越大越慢
- Vite：只需要让变化的模块及其导入者失效，精确到单个模块

### Vite 生产构建

生产模式用 **Rollup** 打包：
- Rollup 的 Tree Shaking 比 Webpack 更彻底（基于 ESM，静态分析）
- 输出更干净的代码（没有 Webpack 的模块运行时 boilerplate）
- 但某些 Webpack 特有的功能 Rollup 不支持（如 Module Federation）

### 插件系统

Vite 插件扩展了 Rollup 的插件接口，并添加了 Vite 特有的钩子：

```js
// Vite 插件示例
export default function myPlugin() {
  return {
    name: 'my-plugin',
    // Vite 独有钩子
    configResolved(config) {
      // 解析最终配置
    },
    transformIndexHtml(html) {
      // 修改 HTML
      return html.replace('<title>', '<title>My App - ');
    },
    // Rollup 通用钩子
    transform(code, id) {
      // 转换模块内容
      if (id.endsWith('.md')) {
        return `export default ${JSON.stringify(code)}`;
      }
    },
    configureServer(server) {
      // 配置开发服务器中间件
      server.middlewares.use('/api', (req, res) => {
        res.end('mock data');
      });
    }
  };
}
```

## Vite vs Webpack 对比

| 维度 | Vite | Webpack |
|---|---|---|
| 开发启动 | 快（不用打包） | 慢（全量编译） |
| HMR 速度 | 毫秒级（模块级） | 秒级（chunk 级，随项目变大变慢） |
| 生产构建 | Rollup（更干净） | Webpack（更灵活） |
| 配置复杂度 | 开箱即用，配置简单 | 配置复杂，学习曲线陡 |
| 生态 | 快速成长，但还不够全面 | 最成熟，几乎什么都能找到插件 |
| CJS 支持 | 通过预构建支持 | 原生支持 |
| 代码分割 | Rollup 的 manualChunks | SplitChunksPlugin，更灵活 |
| 微前端 | 无官方方案 | Module Federation |
| SSR | 有 SSR 支持 | 需要额外配置 |

## 常见追问

### Q: Vite 开发快但生产构建和 Webpack 差距大吗？

**回答要点：**
差距不大。Vite 生产构建用 Rollup，Rollup 本身就很成熟。在 Tree Shaking 上 Rollup 甚至比 Webpack 更好。主要差距在生态丰富度 — Webpack 有一些 Rollup 不支持的高级功能（如 Module Federation、更复杂的代码分割策略）。

### Q: Vite 的开发体验这么好，有什么坑吗？

**回答要点：**
1. **开发和生产不一致** — 开发用 ESM 按需加载，生产用 Rollup 打包，偶尔会有"开发没问题但生产报错"的情况
2. **CommonJS 兼容** — 虽然有预构建，但某些 CJS 依赖的动态 require 场景可能有问题
3. **大项目冷启动** — 依赖预构建首次启动可能慢（特别是大型 monorepo）
4. **HMR 边界情况** — 某些复杂依赖关系下的 HMR 可能不如预期

### Q: 什么情况下你还选择 Webpack 而不是 Vite？

**回答要点：**
1. **微前端** — 需要 Module Federation，这是 Webpack 的独家能力
2. **已有项目** — Webpack 配置已经很完善，迁移成本不值得
3. **特殊 Loader/Plugin** — 某些只有 Webpack 版本的 Loader
4. **构建流水线复杂** — 需要高度定制构建流程的场景

## 回答要点总结

1. Vite 快的核心原因是"开发时不打包"，不是"比 Webpack 写得好"
2. 理解预构建的必要性 — CommonJS 转 ESM + 合并小文件
3. Vite vs Webpack 不是"谁更好"，是"适用场景不同"
4. 能说出 Vite 的坑，说明你用过，不是背的
